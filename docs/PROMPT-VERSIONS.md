# 프롬프트 버전 계약

관리자는 검증 순서 계획과 기록 기반 대화의 **추가 지침**을 편집한다. 기본 출력
계약과 응답 검증은 코드에 고정돼 있으며 편집 화면에서 바꾸지 않는다. 각 용도에
하나의 현재 설정과 최대200개 불변 버전을 보존한다. 저장·버전·요청 영수증·감사를
같은 트랜잭션에 기록한다. DB의 현재 관리자 역할을 다시 검사한다.

기본 설정은 버전0, 빈 추가 지침이다. 빈 내용을 새 버전으로 저장하면 기본값으로
복원한다. 과거 버전과 이미 기록한 호출은 수정하지 않는다. 같은 사용자·용도·요청
ID는 원래 저장 영수증을 재현하고 현재 설정을 다시 적용하지 않는다. 같은 ID로
내용을 바꾸거나 검토 기준 버전이 달라지면409다. 요청 ID는16–80자, 추가 지침은
4,000자 및 UTF-8 8 KiB 이하다.

계획은 `{{goal}}`, 대화는 `{{question}}`만 지원한다. 변수 값은 JSON 문자열로
표시하며 변수 안의 표현식을 다시 확장하지 않는다. 환경변수·파일·셸·네트워크는
미리보기에서 사용하지 않는다. 미리보기는 제공자를 호출하지 않고 작업 실행 권한을
만들지 않는다. 관리자 지침도 모델의 사실성을 보장하지 않는다. 계획의 검사 목록과
대화 인용/형식 검증은 기존 계약을 유지한다.

AI 호출을 준비할 때 용도·버전·템플릿·지문·고정 계약 지문을 고정한다. 호출 시도와
최종 계획/대화 메타데이터에 이 스냅샷을 보존한다. 호출 당시 설정은 인증된
`GET /api/llm/calls` 조회로도 확인할 수 있다. 제공자 응답을 기다리는 동안 설정을
바꿔도 진행 중인 호출의 지침은 바뀌지 않는다. 호출 기록의 관찰·최종 반영은 시작
스냅샷과 일치해야 한다. 새 설정은 이후 호출부터 적용한다. 직접 편집한 DB의 지문이
맞지 않으면 호출을 시작하지 않는다.

화면은 응답 손실 뒤 동일 요청 ID·본문·기준 버전을 유지하고 입력을 잠근다. 충돌은
초안을 보존하며 최신 버전 조회와 기준 선택을 명시적으로 수행한다. 미리보기·조회
완료는 문서 수명·세션·요청 순서와 맞아야 화면에 반영한다. 이력은25개 SQL 페이지다.

- `GET /api/prompts`: 인증된 현재 설정 조회
- `PUT /api/prompts/{planner|conversation}`: 관리자 버전 저장/복원
- `POST /api/prompts/{purpose}/preview`: 인증된 로컬 미리보기
- `GET /api/prompts/{purpose}/history`: 인증된 버전 페이지

현재 범위는 두 용도의 추가 지침이다. Worker/사용자 정의 agent 프롬프트, 종료/시간
제한 프롬프트, 임의 변수 스키마, 실행 중 지침 변경, 모든 모바일·보조 기술,
미확인 저장 요청의 새 문서 복원, 장시간 운영 검수는 후속 범위다. 설치본95→94→95 전환과 두 저장소 백업 복구는 검수했다.
기본 계약 자체가 바뀌는 소프트웨어 업그레이드의 재검토 UI도 후속 범위다.
