# 제공자 모델 목록 조회 계약

등록한 활성 모델 프로필의 고정 수신처에 관리자가 명시적으로 모델 목록을 조회한다.
기존 프로필 또는 용도별 모델 선택은 바꾸지 않는다. 인증 설정이 준비됐다는 표시,
모델 목록 응답, 실제 대화 호출 지원·권한은 서로 다른 결과다. 이 기능은 마지막
대화 호출을 시험하지 않는다.

- `POST /api/model-profiles/{id}/catalog`: 관리자, `expected_revision`과16–80자
  `request_id`가 필요하다. 프로필·현재 관리자·수신처 인증 지문을 DNS 확인 후
  외부 요청 직전에 다시 확인한다.
- 고정된 base 경로 뒤 `/models`에 인증된 GET을 한 번 보낸다. DNS/TLS 고정,
  실행 소유권, 총8초 제한, 최대1MiB JSON·256개 모델·160자 ASCII ID 제한을
  적용한다. 리다이렉트·압축·중복 키·중복 ID·키가 포함된 ID를 거부한다.
- 원문 응답·키·수신처 전체 주소·제공자 부가 메타데이터를 저장하지 않는다.
  당시 프로필 이름·모델·버전·지문, 모델 ID 목록, 응답 해시, 결과와 감사를 저장한다.
- 시작 기록과 감사, 최종 결과와 감사는 각각 같은 트랜잭션이다. 같은 사용자·
  프로필·ID·본문은 원래 저장된 요청을 반환한다. 설정이 이후 바뀌어도 원래 결과를
  현재 설정으로 대체하지 않는다. 같은 ID의 다른 본문은409다.
- 실행 중인 요청의 재확인은 `started` 기록을 반환하며 GET을 추가하지 않는다.
  한 프로세스에서는 하나의 조회만 실행한다. 다른 새 요청은429다. 종료는 진행 중
  요청을 중단하고 기다린다. 소유권이 끊긴 미확정 시작 기록은 재시작 시 `unknown`으로
  기록하며 자동 재조회하지 않는다. 실패·미확정 결과를 다시 시도하려면 새 요청이 필요하다.
- 프로필별 최대200개 조회 기록, 인증된25개 SQL 페이지 이력이다.
  `GET /api/model-profiles/{id}/catalog-history`는 외부 요청을 보내지 않는다.

화면은 응답 손실·429·503 뒤 원래 요청 ID·본문을 유지한다. 같은 요청 결과 확인은
저장된 결과를 재현한다. 충돌 시 최신 프로필을 읽고 사용자가 검토해야 새 요청을
준비한다. 현재 모달을 닫거나 문서를 다시 열 때 미확정 요청 ID를 복원하는 기능은
후속 범위다. 이력에는 기존 시작·실패·미확정 결과도 그대로 표시한다.

소유한 HTTP 제공자와 SQLite/PostgreSQL에서 실제 GET 경로·인증·중복 방지·
프로필/권한/키 변경·감사 실패 롤백·종료·재시작·네이티브 소유권 상실을 검증한다.
전체 패키지·브라우저·호스팅 검사와 전환/복구 결과는 검증 기록에 별도로 남긴다.
제3자 제공자 호환성, 자동 장애 전환, 모델별 대화 연결 시험, 전체 모바일·보조 기술·
장시간 운영은 이 계약의 완료 주장에 포함하지 않는다.
