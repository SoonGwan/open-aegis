# 서명된 범위의 MCP GET 실행 서버

별도 `python -m aegis.mcp_execution_server` 서비스에서 검토된 내장 검사 6개와
관찰 응답 배치 도구를
Streamable HTTP로 실행한다. 운영자가 고정 실행 연결을 설정하고 관리자가 목록을
검토·등록하면 메인 앱에서 해당 서버를 선택해 계획을 만들고 별도로 실행 승인한다.
Worker는 검토된 내장 검사만 호출하고 결과·발견·증거·감사를 원자적으로 저장한다.
일반 플러그인 로더는 아니다. 아래 발급 함수는 신뢰하는 내부 호출자를 위한 기반이다.
HTTP API에서 임의 URL을 받아 권한을 발급하지 않는다.

## 권한과 요청 경계

`aegis.mcp_scope.issue_grant`는 현재 코드 계약을 가진 queued/running 승인 작업의
고정 자산 스냅샷에서만 발급한다. 작업·자산 ID/revision·정확한 URL 범위·검사 ID·
서버 ID·패키지 지문·요청 제한·테스트 계정 환경변수 이름·만료를 HMAC-SHA256으로
서명한다. 기본 유효기간은 60초, 최대 300초다. 승인 시각과 승인된 대기/작업 시간을
넘어서는 권한을 발급하지 않는다. 발급자는 작업 저장소의 승인·현재 상태·취소 여부를
신뢰할 수 있게 읽어야 한다. 현재 함수 자체는 저장소나 사용자 세션을 조회하지 않는다.
고정 서버 확장 `aegis/cancel`은 기존 서명 권한을 검증해 취소를 영속 기록한다.
이미 전송된 요청의 부작용은 되돌리지 않는다.

서버는 대상 요청 전에 서명·서버/검사/코드 계약·만료·계정 허용 목록을 확인한다.
요청 수·시간·속도·재시도는 서명된 제한과 서버 상한 중 더 엄격한 값을 적용한다.
재시도 대기 시간은 더 긴 값을 적용한다. 서버 한 인스턴스는 동시에 한 작업만
실행한다. 동일 데이터 디렉터리의 nonce 기록은 프로세스 간 중복 권한 사용을 막지만
서로 다른 작업의 여러 서버 인스턴스에 대한 전역 속도 제한은 제공하지 않는다.

권한은 대상 네트워크 접근 전에 SQLite 트랜잭션으로 소비한다. 같은 승인 작업·자산·
검사·서버의 재발급은 키 교체 후에도 같은 nonce를 사용하며 전체 승인 유효기간 동안
기록을 유지한다. 네트워크 실패 후에도 소비된다. 자동 재시도 또는 재발급으로 같은
검사를 다시 실행하지 않는다. 응답 손실 후 결과 조회 영수증은 아직 제공하지 않는다.
기록 최대 10,000개에 도달하면 새 실행을 거절한다. 기록을 삭제하거나 다른 디렉터리로
바꾸면 재사용 방지 이력이 사라지므로 운영자는 해당 파일과 시계의 무결성을 관리한다.

기본 응답이 2xx인 경우에만 검사를 완료한다. 401/404/429/5xx 응답은 판정 불가다.
모든 대상 요청은 기존 Transport의 GET·origin/경로·DNS 전체 IP 검사·연결 IP 고정·
TLS·리다이렉트·응답 크기·중지/시간 제한을 적용한다. 사설 대상은 서명과 서버 양쪽의
명시적 허용이 필요하다. 메타데이터·link-local·multicast 주소는 허용하지 않는다.
관찰한 링크를 자동 요청하지 않는다. GET이라는 사실은 대상 서버의 부작용 부재를
증명하지 않는다. 테스트 계정은 서버가 별도로 허용한 `AEGIS_TEST_*` 변수만 읽는다.
서버 인증/서명 값을 계정으로 전달하거나 알려진 비밀이 결과에 반사되면 거절한다.

## 설정

서버에 다음 값을 별도 환경 설정으로 전달한다. 인증 값과 서명 키는 각각 32바이트
이상으로 서로 다르게 설정하고, 운영 환경의 비밀 저장소에서 관리한다.

| 변수 | 용도 |
|---|---|
| `AEGIS_MCP_SERVER_ID` | 클라이언트 연결 및 서명과 동일한 고정 ID |
| `AEGIS_MCP_BEARER_TOKEN` | MCP HTTP 연결 인증 |
| `AEGIS_MCP_SCOPE_KEY` | 신뢰한 발급자와 서버 사이의 서명 키 |
| `AEGIS_MCP_EXEC_DATA_DIR` | nonce 기록 디렉터리, 기본 `data/mcp-execution` |
| `AEGIS_MCP_EXEC_HOST` / `AEGIS_MCP_EXEC_PORT` | 기본 `127.0.0.1:8791` |
| `AEGIS_MCP_EXEC_LAB` | `1`일 때만 사설 대상 허용; 권한의 허용도 필요 |
| `AEGIS_MCP_EXEC_LIMITS` | 선택적 JSON 객체로 지정하는 `RequestLimits` 서버 상한 |
| `AEGIS_MCP_TEST_ENVS` | 허용할 테스트 계정 변수 이름, 쉼표로 구분 |
| `AEGIS_MCP_ALLOWED_ORIGINS` | 허용할 정확한 Origin, 기본 모든 Origin 헤더 거절 |

실행은 `python -m aegis.mcp_execution_server`로 한다. 외부 연결에는 HTTPS 프록시와
별도 네트워크 접근 제한이 필요하다. 소유한 loopback 시험에서만 SDK의 명시적
`lab_http=true` 설정을 사용한다. 서버는 `/mcp` POST JSON-RPC, stateless 초기화·
목록·호출과 initialized 알림, 서명 권한의 `aegis/cancel` 확장을 제공한다.
표준 MCP 취소 알림·SSE 구독·세션 재개는 제공하지 않는다.
HTTP 본문은 64 KiB, 반환 JSON은 512 KiB 제한을 적용한다. 인증·Origin 검사 후
호출을 처리하며 access log를 끈다. 요청 권한이나 인증 원문을 오류 응답에 반환하지 않는다.

## 메인 앱의 실행 연결

메인 앱에는 `AEGIS_MCP_CONNECTIONS`로 고정 endpoint를 등록하고, 별도로 다음
실행 연결을 설정한다. 연결의 Bearer 환경변수와 서명 키는 서로 다르게 관리한다.
서버의 `AEGIS_MCP_SERVER_ID`는 연결 ID와 같아야 한다. 다음은 비밀이 없는 설정 예다.

```json
[{"connection_id":"security-worker","scope_key_env":"AEGIS_MCP_SCOPE_WORKER","allow_private":false}]
```

위 JSON을 `AEGIS_MCP_EXECUTORS`에 넣고 `AEGIS_MCP_SCOPE_WORKER`에는 서버와
공유하는 별도 서명 키를 설정한다. 최대 10개 연결을 허용한다. 시스템 설정에서 실제
목록·입력/결과 스키마·실행 상한을 검토하고 등록한다. 현재 패키지의 6개 GET 도구 및 관찰 응답 배치 도구와
정확히 일치하는 정의만 실행 후보가 된다. 등록은 작업 실행 승인이 아니다.

새 작업의 실행 위치에서 서버를 명시적으로 선택한다. 기본값은 로컬이다. 작업에는
연결 URL·인증/키 지문·전체 목록 지문·선택 도구 revision/정의·서버 상한을 저장한다.
관리자 승인 시 목록을 다시 확인하며 승인/감사는 한 트랜잭션으로 기록한다. Worker는
전송 직전 현재 승인·자산 revision/URL·권한·설정과 도구를 다시 대조한다. 재계획·발견
재검증·후속 계획도 원격 연결을 보존하되 새 승인이 필요하다. 관찰 응답 선택 작업의
원격 어댑터는 아래의 별도 배치 도구로 실행한다.

자산별 승인 요청 예산은 여러 검사에서 공유한다. 검사 전송 기록을 저장한 다음
최소 환경의 감독된 자식 프로세스가 실제 RPC를 호출한다. 전체 목록/선택 도구 변경,
중지 또는 시간 제한이면 호출/결과 반영을 거절한다. 실패·응답 손실·재시작 시 전송
기록은 `unconfirmed`로 남기고 자동 재호출하지 않는다. 메인 앱 중지는 이후 전송과
결과 저장을 막고 별도의 최대3초 감독된 클라이언트로 서버에 취소를 요청한다.
전송 후 오류·결과 거절에도 같은 권한의 취소를 요청한다. 실행 기록과 전송 이력은
취소 확인 `acknowledged`와 미확인 `unconfirmed`를 구분한다. 취소 확인은 서버의
권한 폐기 기록이며 이미 전송된 요청의 부작용 취소나 원격 실행 attestation은 아니다.

## 결과 검증과 남은 통합

`validate_execution_response`는 전체 결과를 먼저 검사한다. 권한 해시·작업/자산/
revision·검사·범위·코드 지문·유효 제한을 대조하고 기존 내장 결과 계약을 적용한다.
트래픽은 범위 내 GET, 허용 IP, 상태/크기/시도 횟수와 본문 해시를 검사한다. 헤더·
원문 응답 본문·인증 값은 결과에 넣지 않는다. 하나라도 잘못되면 전체 결과를 거절한다.
수신자는 검토한 서버 상한과 사설 대상 허용 설정을 명시적으로 전달해야 한다.

코드 지문과 서명은 신뢰한 발급자/서버 사이의 권한·호환성 검사다. 원격 구현의 진실성,
실제 실행 여부, 반환 증거의 진위 또는 OS 격리를 증명하지 않는다. 서버 OS·설정·키
소유자는 신뢰한다. 현재 고정 코드의 협력적 요청 제한이며 임의 플러그인의 CPU/RSS·
파일시스템·egress sandbox는 아니다. 독립 플러그인 계약/격리, 장애 후 취소 확인과
전체 운영 호환 검수가 완료되기 전 v1 완료로 표시하지 않는다.

## 내부 결과 저장 기반

`aegis.mcp_result_store.admit`는 검증된 전체 결과를 메인 저장소의 단일 쓰기
트랜잭션으로 반영하는 내부 함수다. 구성된 원격 Worker가 호출하며 임의 결과 업로드
HTTP API는 제공하지 않는다. 원격 작업에는 사전 전송 기록도 대조한다.
호출자가 제공한 작업을 제한된 JSON 복사본으로 고정하고, 서명 권한이 그 승인
스냅샷에서 발급 가능한 정확한 권한인지 재생성해 비교한다. 트랜잭션에서 현재 작업의
running 상태·승인/범위/도구/정책 계약·현재 자산 revision/URL·커버리지 상태를 다시
확인한다. 관찰 응답 배치는 선택한 모든 URL·검사 조합과 계획 순서까지 대조한다.

발견·증거·발견 이력·관찰 링크·트래픽·완료/건너뜀 커버리지·반영 영수증·감사 이벤트는
같은 DB 연결로 저장한다. 저장/감사 실패는 전체를 롤백한다. 하나의 작업·자산·검사·
서버 조합에는 하나의 결과만 반영한다. 유효기간 내 동일 권한/결과/승인 계약의 재전달은
원래 영수증을 반환하며, 결과가 달라지면 거절한다. 완료된 작업에서도 이미 반영한 동일
영수증 재전달은 추가 저장하지 않는다. 만료 후 재전달과 응답 손실 후 원격 결과 조회는
아직 지원하지 않는다. 영수증은 로컬 계약 검사와 저장의 기록이며 원격 실행 attestation이 아니다.

원본 권한·서명 키·알려진 추가 인증 값이 결과에 반사되면 반영하지 않는다. 추가 인증 값은
신뢰한 통합 호출자가 명시적으로 전달해야 한다. 임의 비밀을 전부 식별하는 기능은 아니다.
메인 승인·목록 변경 재검토·Worker 호출과 저장은 연결했다. 원격 취소는 연결했으며 장애 후 취소 확인·일반
플러그인 격리·전체 운영 검수는 남아 있으므로 이 통합만으로 v1 완료를 선언하지 않는다.


## 서명 권한 취소의 경계

`aegis/cancel`은 `/mcp`의 별도 고정 JSON-RPC 메서드이며 입력은 `grant` 하나다.
기존 HTTP Bearer/Origin/프로토콜/본문 한도와 권한 HMAC·서버/코드·만료 검사를
적용한다. 목록의 `cancellation=signed-grant-v1` 정의도 관리자 검토 계약에 포함한다.
서버는 취소와 소비 이력을 같은 SQLite 쓰기 트랜잭션으로 기록한 뒤, 권한 해시에
귀속한 확인을 반환한다. 취소는 실행 권한을 만들거나 대상 요청을 보내지 않는다.
실행 전에 취소하면 늦게 도착한 권한도 소비 이력으로 거절한다. 같은 취소는 중복
기록 없이 확인할 수 있으며 nonce 전체 승인 유효기간 동안 보존한다. 최대10,000개
소비 이력이 가득 차도 기존 권한의 취소는 가능하다. 취소 테이블은 이 소비 이력의
부분집합이다. 기존 2열 소비 테이블을 바꾸지 않아 이전 SQL 쓰기 형식도 유지한다.

실행 제어는 후속 요청/대기/결과 반환 전에 취소 저장소를 확인한다. 진행 중인 응답은
기존 RequestGuard가 소켓을 닫아 중단한다. 같은 ledger를 쓰는 다른 프로세스도
취소를 읽는다. 저장소 읽기 실패 시 검사를 중단한다. 한 권한의 취소는 서버 전체
종료나 다른 권한의 취소가 아니다. 연결 손실·확인 손실·만료·키/서버 교체 또는 메인
프로세스 강제 종료에서는 즉시 원격 취소가 확인되지 않을 수 있다. 서버의 서명 만료와
검사/요청 상한은 계속 적용되며 메인 앱은 미확인 실행을 자동 재호출하지 않는다.

SDK `cancel_scoped`는 초기화한 별도 Client에서 호출한다. 한 Client의 작업은
직렬화하므로 진행 중인 호출을 취소할 때 같은 Client의 잠금을 기다리지 않는다.
통합 Worker는 새 감독된 자식 프로세스를 사용하고 메인 중지 이벤트와 독립적인
3초 정리 deadline을 적용한다. SDK의 신뢰한 `operation_timeout`은 실제 소켓과
RequestGuard에도 적용되며 기본12초와 전체 TaskControl deadline은 유지한다.

## 관찰 응답 배치

`validate_observation_responses`는 관리자가 별도로 검토·등록해야 하는 일곱 번째
고정 MCP 도구다. 검사 종류는 기존 6개를 유지한다. 완료한 출처 작업에서 선택한
최대 10개 URL과 40개 URL·검사 조합만 서명한다. 허용 검사는 보안 헤더·전송 보안·
쿠키 정책·CORS 정책이며 API 권한 검사는 포함하지 않는다. 출처 작업·선택 지문·
계획 순서·현재 자산 범위를 승인과 전송/저장 시 다시 검사한다.

원격 연결은 출처 작업에서 상속한다. 선택하지 않은 기본 URL이나 새로 발견한 링크는
요청하지 않는다. 각 선택 URL의 응답은 배치 내에서 재사용하며 요청 예산은 모든 URL이
공유한다. URL별 2xx 확인에 실패하면 해당 검사 조합은 실패로 기록한다. 유효한 부분
결과의 발견·증거는 보존하고 다음 계획은 남은 조합만 새 승인 후 실행한다. 발견
재검증도 같은 URL과 원격 연결을 보존한다.

결과는 정확한 선택 행·순서·URL·검사·상태·트래픽 계약을 만족해야 한다. 잘못된 결과나
감사 저장 실패는 배치 전체 반영을 롤백한다. 유효한 결과는 실제 검사별 커버리지와
URL별 결과, 출처를 가진 발견·증거, 한 배치 영수증을 같은 트랜잭션으로 저장한다.
중지는 후속 요청과 결과 반영을 막고 기존 서명 취소 확인을 기록한다. 메인 프로세스
강제 종료 후의 영속 취소 재전송 큐와 원격 실행 attestation은 아직 제공하지 않는다.
