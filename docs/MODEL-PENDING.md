# 새 문서의 미확인 모델 요청 복구

모델 프로필 생성·편집, 워크스페이스 용도별 선택, 기존 작업의 모델 선택,
제공자 목록 조회·연결 시험은 전송 전에 원래 요청 ID·본문·작성 시간을
브라우저의 해당 origin 로컬 저장소에 보존한다. 요청 결과의 권한·버전·불변 이력은
계속 서버가 판정한다. 브라우저 기록 자체는 실행 권한이나 완료 증거가 아니다.

새로고침 후 같은 편집기를 열면 이전 요청을 명시적으로 선택할 수 있다.
선택이나 화면 진입만으로 요청을 보내지 않는다. 같은 요청 확인 버튼은 원래 ID·본문을
보내므로 서버 영수증이 남아 있다면 원래 결과를 읽고 제공자를 다시 호출하지 않는다.
서버가 시작 영수증을 저장하지 못한 경우에는 기존 서버 입장 검사가 적용된다.
백업 롤백·복제한 서버·삭제한 영수증까지 외부 요청 한 번을 보장하지 않는다.

기록은 계정 ID·리소스·HTTP 메서드·요청 ID별로 분리한다. 다른 탭의 별도 ID를 덮어쓰거나
현재 결과를 확인하면서 지우지 않는다. 기록은 작성 후24시간, 리소스당 최대20개,
항목당 UTF-8 최대4096바이트다. 만료된 정상 기록은 읽을 때 제거한다.
형식·본문 허용 필드·경로·ID·시간·크기 검사를 통과하지 못하면 복구와 새 요청을 막고
명시적 해당 리소스 정리를 안내한다. 인증 토큰·쿠키·제공자 키·응답 내용은 보존하지 않는다.
프로필 이름·모델 이름·수신처 ID와 검토 버전은 원래 본문에 포함되므로 해당 브라우저에 남는다.

보존할 수 없으면 전송 전에 멈춘다. 통신 실패·503·429·인증/권한 실패·아직 시작 상태인
영수증은 미확인 기록을 유지한다. 현재 세션/화면의 종료된 성공이나400/404/422 응답을
확인하면 그 요청만 정리한다.409는 원래 요청을 유지한다. 최신 설정을 명시적으로
검토하고 채택하면 이전 요청 확인을 끝내고 새 ID로 작성한다. 프로필 초안은 원래
입력 내용을 복원하며 최신 버전 채택 후에도 초안을 유지한다.

성공한 명시적 로그아웃은 현재 계정의 브라우저 기록을 정리한다. 서버 이력은 남는다.
세션 만료에는 기록을 유지해 같은 계정 재로그인 후 확인할 수 있다. 계정별 컴포넌트와
기존 세션/화면 수명 검사가 이전 응답의 현재 편집기 반영을 제한한다.
명시적 브라우저 정리는 서버 요청을 취소하거나 되돌리지 않는다. 새 요청은 별도
저장 또는 제공자 비용을 만들 수 있으므로 먼저 서버 이력을 확인한다.

## 검수 범위

프런트엔드114개 검사에는 만료·다중 ID 분리·계정/작업/메서드 분리·정확한 정리·손상/
크기/미래 시간·허용하지 않은 인증 필드·용량 실패·상한 검사가 포함된다.
소유한 임시 서버와 실제 브라우저에서 프로필 편집·용도별 선택·작업 선택·연결 시험·
목록 조회의 성공 응답 유실→새 문서→명시적 같은 요청 확인을 검수했다.
새 문서나 요청 선택만으로 추가 전송이 없고, 같은 ID/본문 확인 후 저장/제공자 요청이
중복되지 않았다. 연결 시험은 당시 모델 응답을 현재 프로필 변경 후에도 읽었다.
실제409 초안 복구의 입력 불일치를 재현하고 수정한 뒤 최신 버전 채택/새 ID 저장을 검수했다.
작업 범위·승인·실행 상태, 호출/대상 트래픽과 감사 연결도 비교했다.
소유한 브라우저 오류 제어 화면으로 저장 용량 실패를 만들어 API/제공자 요청0건을 확인했다.
로그아웃/재로그인의 브라우저 기록 정리와 서버 이력 유지도 확인했다.

Python·저장소·API는 검수한 연결 시험 소스와 동일하다. 이번 변경의 검수는 UI에 한정하며
패키지/백엔드 전체 검사를 새로 실행했다고 주장하지 않는다. 추가 실제 브라우저에서는 첫 관리자 연결 응답을 서버에서 완료한 뒤 보류하고,
다른 탭의 정상 비밀번호 재설정으로 첫 계정의 세션을 만료시켰다. 다른 관리자 로그인과
별도 응답 유실 요청 후 첫 응답을 전달해도 두 번째 계정 기록이 남았고, 첫 계정도
새 비밀번호 재로그인 후 원래 요청을 복구했다. 두 계정의 동일 ID/본문 재확인에서
실제 제공자 POST2개·불변 영수증2개를 유지했다. 만료/다른 계정의 복구 내용 분리와
늦은 응답 무반영을 이 순서에서 확인한 것이다. 임의의 모든 탭/인증 교체 타이밍,
전체 모바일/보조 기술·장시간 운영은 추가 검수 범위다. GitHub 검증은 별도 실행 기록으로 추적한다.
