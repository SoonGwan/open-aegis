# 기록 기반 대화와 답변 출처

작업 대화는 저장된 작업과 발견 사항의 규칙 기반 요약이다. 외부 모델을 호출하거나
추가 검증을 실행하지 않는다. 질문의 ‘수정/조치/우선/해결’ 표현은 조치 안내를
선택하며, 그 외에는 발견 판정 유형과 상태를 요약한다.

새 답변은 `provenance.version=1`, `mode=recorded_rules`, 조회 시각,
연결된 발견 사항 전체 수와 `citations`를 저장한다. 작업, 우선순위가 높은
최대 8개 발견 사항을 한 SQLite 읽기 트랜잭션에서 조회한다. 작업 상태·처리 수·
완료한 검증 수·오류 수와 인용한 발견의 제목·답변에 사용한 필드만 당시 값으로
남긴다. 발견의 증거 ID 배열·응답 원문·지문은 출처에 복사하지 않는다.
전체 발견 수가 8개를 넘으면 답변에 일부 선택임을 명시한다.

답변 본문의 `[작업]`, `[발견 1]` 등은 ‘답변 출처’의 항목에 대응한다.
이 영역을 펼치면 당시 기록과 조회 시각을 확인할 수 있다. ‘현재 기록 열기’는
현재 작업 또는 발견 상세로 이동하므로, 답변 당시의 값과 다를 수 있다.
과거 답변에는 출처를 소급 생성하지 않는다. 기록에 사용자가 넣은 민감한 제목이나
조치 안내가 있다면 답변에도 포함될 수 있으며 자동 비밀 탐지를 보장하지 않는다.

질문·답변의 저장은 원자적이다. 기존 전송 ID 재시도는 원래 답변과 출처를 반환하며,
동일 ID에 다른 질문을 보내면 409다. 조회 권한은 인증된 세 역할, 질문 저장 권한은
admin/operator다. 새 답변의 출처가 저장된 뒤 원본 상태가 바뀌어도 출처는 유지된다.
저장 데이터 자체를 변조할 수 있는 관리자를 상대로 역사적 진실이나 서명을 보장하는
기능은 아니다. 작업 상세의 JSON/Markdown 보고서는 대화 이력 내보내기가 아니다.

현재 인용은 작업·발견 기록이며 개별 증거 내용 인용이나 AI 근거 검증은 제공하지 않는다.
외부 모델 대화, 실행 제안·승인·개입, 다른 Worker 관찰 통합, 기기 간 미확인 질문
복원, 전체 모바일·스크린리더 여정은 별도 v1 요구사항으로 남아 있다.
