# 기록 기반 대화와 답변 출처

작업 대화의 기본은 저장된 작업과 발견 사항의 규칙 기반 요약이다. 기본 방식은
외부 모델을 호출하지 않는다. 질문의 ‘수정/조치/우선/해결’ 표현은 조치 안내를
선택하며, 그 외에는 발견 판정 유형과 상태를 요약한다.

새 답변은 `provenance.version=1`, `mode=recorded_rules`, 조회 시각,
연결된 발견 사항 전체 수와 `citations`를 저장한다. 작업, 우선순위가 높은
최대 8개 발견 사항을 한 SQLite 읽기 트랜잭션에서 조회한다. 작업 상태·처리 수·
완료한 검증 수·오류 수와 인용한 발견의 제목·답변에 사용한 필드만 당시 값으로
남긴다. 발견의 증거 ID 배열·응답 원문·지문은 출처에 복사하지 않는다.
전체 발견 수가 8개를 넘으면 답변에 일부 선택임을 명시한다.

각 발견에는 이 작업에서 관찰한 증거 중 최근 저장된 한 개를 연결한다. 발견의 참조
목록에 있는 증거라도 자산·도구·지문·작업 소속이 일치해야 하며, 다른 재검증 작업의
증거는 이 작업의 출처로 사용하지 않는다. 조회는 같은 읽기 트랜잭션에서 수행한다.
증거 ID·작업 ID·자산 ID·도구·관찰 시각과 관찰 JSON을 당시 값으로 저장한다.
JSON은 앞부분 최대 4,096자만 저장하고 잘림 여부를 명시한다. 저장된 증거 내용은
원래 검증 도구의 관찰 자료이며 전체 HTTP 응답이나 실제 유출을 입증하는 자료가 아니다.
일치하는 증거가 없거나 최근 기록의 형식/시각을 확인할 수 없으면 출처 누락을 알린다.
추정한 증거를 생성하거나 다른 작업의 증거로 대체하지 않는다.

답변 본문의 `[작업]`, `[발견 1]` 등은 ‘답변 출처’의 항목에 대응한다.
이 영역을 펼치면 당시 기록과 조회 시각을 확인할 수 있다. ‘현재 기록 열기’는
현재 작업 또는 발견 상세로 이동하므로, 답변 당시의 값과 다를 수 있다.
`[증거 1]` 등은 해당 발견 아래의 관찰 발췌에 대응한다. ‘현재 증거 열기’는 발견의
증거 이력을 펼치고 증거 ID로 검색한다. 증거 ID 검색도 서버의 출처 검사를 유지하며,
조회 중 원본이 삭제/변경되면 당시 발췌는 남아 있어도 현재 목록은 달라질 수 있다.
과거 답변에는 출처를 소급 생성하지 않는다. 기록에 사용자가 넣은 민감한 제목이나
조치 안내가 있다면 답변에도 포함될 수 있으며 자동 비밀 탐지를 보장하지 않는다.

질문·답변의 저장은 원자적이다. 기존 전송 ID 재시도는 원래 답변과 출처를 반환하며,
동일 ID에 다른 질문을 보내면 409다. 조회 권한은 인증된 세 역할, 질문 저장 권한은
admin/operator다. 새 답변의 출처가 저장된 뒤 원본 상태가 바뀌어도 출처는 유지된다.
저장 데이터 자체를 변조할 수 있는 관리자를 상대로 역사적 진실이나 서명을 보장하는
기능은 아니다. 작업 상세의 JSON/Markdown 보고서는 대화 이력 내보내기가 아니다.

현재 인용은 작업·발견과 출처가 검증된 관찰 기록이다. AI 답변의 사실성·각 문장과
증거의 논리적 일치를 독립적으로 검증하지 않는다.
실행 제안·승인·개입, 다른 Worker 관찰 통합, 기기 간 미확인 질문
복원, 전체 모바일·스크린리더 여정은 별도 v1 요구사항으로 남아 있다.

## 선택적 AI 초안

서버에 `AEGIS_LLM_CHAT_ENABLED=1`, `AEGIS_LLM_API_KEY`, `AEGIS_LLM_MODEL`을
설정한 경우 운영자가 답변 방식에서 AI 초안을 선택할 수 있다. 기본은 꺼져 있으며
Planner의 AI 선택만으로 대화 호출이 생기지 않는다. 호환 제공자 주소는
`AEGIS_LLM_BASE_URL`이다. HTTPS·주소 검사·인증 값 리디렉션 금지·1 MiB 응답
제한과 8초 제공자 요청 제한은 기존 completion 전송을 사용한다. HTTP loopback은
명시된 실험 모드의 합성 제공자 예외다.

질문과 현재 읽기 스냅샷의 작업·발견 필드 및 관찰 발췌를 제공자로 보낸다.
사용자 입력과 관찰 값에 민감한 정보가 있으면 외부 수신자에게 전달될 수 있다.
전체 대화 이력·타 작업 자료·원본 HTTP 응답·인증 값·증거 지문은 프롬프트에
포함하지 않는다. 프롬프트 JSON이 UTF-8 64 KiB를 넘으면 호출 전에 413으로 거절한다.

제공자는 최대 12개의 `{text, citations}` 블록을 반환한다. 각 문장은 최대
1,500자이고, 인용 배열은 현재 전달된 `[작업]`·`[발견 n]`·`[증거 n]` 번호만
허용한다. 외부 출처·누락 인용·실행 필드·잘못된 JSON/형식은 거절한다.
제공자 답변 텍스트가 설정된 서버 API 키를 그대로 포함하면 거절한다. 다른 비밀값의
자동 탐지나 변형/인코딩된 키의 탐지를 보장하지 않는다.
수용한 답변은 `provenance.mode=recorded_ai`이며 화면에서 AI 초안이라고 명시한다.
이 검사는 출처 소속·출력 형식 검사로, 환각이나 악성 지시의 텍스트 출력을
완전히 차단하는 의미 검사가 아니다. 서비스는 초안의 명령·URL을 실행하지 않는다.

형식 거절 또는 제공자 실패 시 같은 요청은 규칙 요약으로 복구한다. 제공자의 거절된
텍스트나 오류 본문은 저장하지 않는다. `assistant_generation`은 설정 모델,
`accepted`/`invalid_answer`/`request_failed`, 조회 시각, 검증된 토큰 사용량을 저장한다.
이 메타데이터·질문·답변·감사 이벤트는 하나의 쓰기 트랜잭션이며 실패 시 롤백한다.
응답을 받지 못한 사용량은 미확인이다. 숫자 검증은 [LLM-USAGE.md](LLM-USAGE.md)를 따른다.

AI 요청은 전송 ID가 필수다. 이미 저장된 동일 질문/방식/전송 ID는 원래 답변을
반환하고 재호출하지 않는다. 다른 질문이나 방식은 409다. 한 서비스 프로세스에서
동시에 한 AI 호출만 허용하며 대기 호출은 429/Retry-After로 거절한다. 같은 전송
ID로 재시도한다. 세션·역할을 제공자 응답 후 다시 확인하고, 폐기된 세션이나 종료 중
서버는 답변을 저장하지 않는다. 이 경우와 감사 저장 실패·방식 경합에서 이미 소비한
제공자 토큰은 대화 기록에 남지 않을 수 있다. 청구 원장이나 제공자 중복 요청 방지를
보장하지 않는다. 프로세스가 호출 후 저장 전에 중단되면 재시도로 재호출할 수 있다.

대화 호출은 메시지별 기록이다. 설정의 마지막 Planner 호출 집계에는 포함하지 않으며,
가격·비용 계산과 대화 전체 사용량 대시보드는 아직 없다. 실제 상용 제공자·모델과
프롬프트 공격의 의미적 대응·전체 모바일/접근성 검수는 합성 제공자 검증과 구분한다.
