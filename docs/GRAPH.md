# 실제 기록의 관계 그래프

탐색 경로는 자산과 검증 계획을 선택해 기록의 연결을 탐색하는 화면이다.
워크스페이스 전체의 자산과 발견을 임의로 한 줄로 이어 붙이지 않는다.
자산·작업 선택기는 서버 검색과 페이지를 제공하며 보관된 자산도 선택할 수 있다.
기본 작업은 해당 자산의 가장 최근 생성한 계획이다. 승인 대기 계획도 선택할 수 있고,
도구 노드의 상태로 계획과 실행 결과를 구분한다.

| 연결 | 확인하는 기록 |
|---|---|
| 자산 → 작업 | 작업의 `scope_snapshot`에 실제로 포함된 자산 |
| 작업 → 검증 도구 | 작업에서 선택한 도구와 해당 자산의 도구별 결과 |
| 검증 도구 → 발견 | 자산·도구 일치, 발견의 `task_ids`에 해당 작업 포함 |
| 발견 → 증거 | 발견의 `evidence_ids` 참조, 증거의 자산·작업·도구·지문 모두 일치 |
| 엔드포인트 관찰 도구 → 관찰 링크 | 해당 자산·작업에서 남긴 링크 관찰 기록 |

작업→도구 연결은 선택한 도구를 뜻하며 검증 완료를 보증하지 않는다.
건너뜀·실패·미실행·이전 범위를 도구 노드에 그대로 표시한다.
다른 작업에서 남긴 증거는 유효한 과거 이력이더라도 선택한 작업의 증거로 연결하지 않는다.
누락되거나 자산·도구·지문이 다른 증거 참조는 연결하지 않고 수를 표시한다.
중복 참조는 증거 노드 하나로 표시한다. 도구별 결과의 자산·작업·도구가 기록 키와
일치하지 않아도 원래 계획의 도구를 ‘기록 없음’으로 표시하며 다른 도구로 바꾸지 않는다.
관찰 링크는 HTML에서 발견한 주소이며 그 주소에 실제 검증 요청을 보냈다는 뜻이 아니다.

노드를 선택하면 직접 연결된 기록과 상세 근거를 확인할 수 있다. 직접 연결 버튼은
실제 엣지를 따라 이동하며 키보드 Enter로 선택했을 때 목적 노드로 포커스를 옮긴다.
발견 상세 열기는 기존 증거·재검증 화면으로 연결된다. SVG 연결선에는 접근성 트리를
중복 생성하지 않고, HTML 버튼과 직접 연결 목록으로 관계를 읽을 수 있게 한다.
그래프 영역의 좌우/상하 이동, 80/100/120% 확대, 목록 보기와 필터 접기를 제공한다.
모바일에서는 필터를 기본으로 접고 선택·필터 변경 버튼으로 연다.
선택 노드는 처음 로드할 때 보이게 이동하되 자동 갱신마다 사용자의 스크롤을 되돌리지 않는다.

`?page=graph` 및 `graph_asset`, `graph_task`, `graph_check`, `graph_severity`,
`graph_status`, `graph_offset`, `graph_snapshot`, `graph_node`에 선택 범위와 노드를 저장한다.
북마크를 다시 열어 선택한 증거까지 복원할 수 있다. 선택한 노드가 현재 표시 범위에
없으면 이를 설명하며 필터·페이지 또는 발견 상세를 사용하도록 안내한다.
다른 화면의 검색·페이지 전체 URL 상태 보존은 별도 미완료 항목이다.

## API와 조회 상한

인증된 관리자·운영자·조회자는 `GET /api/graph?asset_id=…&task_id=…`를 읽을 수 있다.
`task_id` 생략 시 해당 자산의 최근 생성한 작업을 사용한다. 작업이 없으면 자산 노드만
반환한다. 없는 자산·작업 또는 해당 자산이 포함되지 않은 작업은 404이다.
`check`, `severity`, `status`는 검증 도구·발견의 필터이며 허용하지 않는 값은 422이다.

- 발견: 기본 10개, 최대 25개. `offset`과 삽입 상한 `snapshot`으로 페이지를 순회한다.
- 증거: 발견마다 해당 작업의 최근 2개. 생략한 수와 전체 이력 참조 수를 표시한다.
- 관찰 링크: 해당 작업의 최근 10개. 생략한 수를 표시한다.
- 노드: 최대 자산 1 + 작업 1 + 도구 6 + 발견 25 + 증거 50 + 관찰 10 = 93개.

API는 한 SQLite 읽기 트랜잭션에서 연결과 건수를 구한다. 전체 증거 ID 목록을
응답에 넣지 않고 SQL로 필요한 참조를 조회한다. 그래프 조회·노드 이동·필터·확대는
대상 서버에 HTTP 요청을 보내거나 실행 승인을 변경하지 않는다.
발견 상세의 전체 증거 조회는 현재 별도의 무제한 조회 정리 항목으로 남아 있다.

검증: `tests/test_graph.py`는 교차 자산/작업/도구/지문 제외, 누락 참조,
중복 노드, 페이지 간 중복 방지, 결과 상한과 생략 수, 보관 범위 revision,
승인 전 무요청과 조회 후 무요청, 잘못된 필터/인증, 10,001개 증거 참조의
작은 응답 및 결과 키 불일치의 실패 전·수정 후 재현을 검사한다.
`tests/test_identity.py`는 조회자에게 그래프 읽기를 허용하면서 변경을 금지하는 것을 검사한다.
브라우저에서 검증 도구 필터, 발견→증거 이동과 원본 관찰 값, 증거 북마크 복원,
Enter 이동의 실제 포커스 및 390px 모바일 그래프/목록의 문서 폭을 확인했다.
모든 화면의 스크린리더 감사 또는 장시간 부하 검증을 마쳤다는 뜻은 아니다.
