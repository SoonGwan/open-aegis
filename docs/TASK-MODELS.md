# 작업별 모델 선택 계약

관리자는 기존 작업의 검증 순서 계획·기록 기반 대화에 사용할 모델 프로필을 각각
선택할 수 있다. 프로필과 인증 설정의 현재 버전을 검토해야 하며 최대200개 불변
선택 버전과25개 SQL 페이지 이력을 보존한다. 현재 선택·이력·요청 영수증·감사는
같은 트랜잭션이다. 작업 모델 선택은 범위·도구·계획·실행 승인을 변경하지 않는다.

선택은 이후 계획 재작성과 대화 호출에 적용된다. 최초 작업 생성과 새 후속 작업은
워크스페이스 용도별 기본값을 따른다. 저장한 작업의 프로필 고정은 다른 작업에
전파하지 않는다. 프로필 고정을 해제하면 이후 호출마다 워크스페이스 선택을 따른다.
고정 프로필·키·관리자 검토가 바뀌면 재검토가 필요하며 다른 프로필로 자동 전환하지
않는다. 기존 계획 규칙 복구는 유지되며 AI 대화는 사용할 설정이 없으면 차단한다.

관리자 저장에는 현재 선택 버전, 현재 작업 보관 버전, 선택할 프로필 버전과
16–80자 요청 ID가 필요하다. 같은 사용자·작업·용도·ID·본문은 원래 영수증을
반환하고 현재 선택을 과거 버전으로 되돌리지 않는다. 달라진 본문 또는 최신 버전
충돌은409다. 작업 보관 중에는 새 선택을 저장하지 않는다. 저장된 작업 참조와
보관 버전의 손상은 모델 사용을 막는다.

호출 당시 기록에는 작업 ID·용도·선택 버전·프로필 참조·지문을 추가한다.
호출 직전 선택·프로필·수신처 인증 설정을 다시 확인한다. 진행 중인 기존 호출은
원래 스냅샷을 보존하고, 같은 대화 요청 ID의 재확인은 새 모델을 호출하지 않는다.
키·전체 수신처 URL은 선택·이력에 저장하지 않는다. 호출 영수증의 제공자 origin은
기존 사용량 계약을 따른다.

화면은 작업 상세에 있으며 응답 손실 때 ID·본문·기준 버전을 유지한다. 충돌은
최신 작업 선택과 프로필을 명시적으로 읽고 사용자가 채택해야 새 요청을 작성한다.
대화의 AI 선택 가능 여부는 작업 모델과 설치자의 별도 대화 허용 설정을 함께
확인한다. 이 표시는 실제 제공자 연결 성공을 증명하지 않는다.

- GET /api/tasks/{task_id}/models: 인증된 현재 작업 선택/설정 상태
- PUT /api/tasks/{task_id}/models/{planner|conversation}: 관리자 버전 저장
- GET /api/tasks/{task_id}/models/{purpose}/history: 인증된25개 SQL 페이지 이력

작업 생성 시 프로필 선택, 임의 사용자 agent 모델, 장애 자동 전환, 새 문서의
미확인 편집 복원, 모든 모바일·보조 기술·장시간 운영은 별도 범위다.
독립 브랜치에서 설치 패키지553개 테스트와 두 저장소의98→97→98 전환·오프라인
백업 복원, 브라우저 응답 손실·두 탭 충돌 검수를 통과했다. 구버전97은 작업별
선택을 해석하지 못하므로 AI 인증과 대화를 끈 유지보수 상태에서 기록 보존만
검증했다. 전체 native 테스트와 GitHub 검증은 아직 진행 중이다.
