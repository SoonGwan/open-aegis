# ScopeSentry 자산 가져오기와 출처

현재 제공하는 연동은 ScopeSentry의 **asset JSON 내보내기 파일**을 검토하고 반영하는
수동 동기화다. 원격 서버 연결·인증·자동 페이지 수집은 아직 구현하지 않았다.
파일을 나누어 순차적으로 가져올 수 있으며 반복 반영은 원본 식별자로 중복을 방지한다.

## 확인한 원본 계약

2026-10-04 확인한 ScopeSentry 기준 커밋은
[`8203c4932795f35d741dd54871345b9eca0943a8`](https://github.com/Autumn-27/ScopeSentry/commit/8203c4932795f35d741dd54871345b9eca0943a8)이다.
[내보내기 서비스](https://github.com/Autumn-27/ScopeSentry/blob/8203c4932795f35d741dd54871345b9eca0943a8/internal/services/export/export.go)는
MongoDB 문서를 JSON 인코더로 한 개씩 기록한다. 따라서 확장자가 `.json`이어도
한 줄에 객체 하나인 NDJSON이며 최상위 JSON 배열이 아니다.
[자산 모델](https://github.com/Autumn-27/ScopeSentry/blob/8203c4932795f35d741dd54871345b9eca0943a8/internal/models/asset.go)과
원본 내보내기 투영을 대조했다. ObjectID의 문자열 표현은
[MongoDB Go 드라이버](https://github.com/mongodb/mongo-go-driver/blob/v1.17.6/bson/primitive/objectid.go)의
JSON 직렬화와 일치한다. 이것은 원본 서비스 전체를 운영하거나 감사한 결과가 아니다.

새 어댑터는 독립 구현이며 원본 코드를 런타임에 포함하지 않는다. 형식은
`scopesentry-asset-ndjson-v1`이다. 현재 HTTP 자산만 처리한다.

```json
{"_id":"000000000000000000000001","type":"http","url":"https://owned.example/"}
{"_id":"000000000000000000000002","type":"http","url":"https://owned.example/api/"}
```

ScopeSentry에서 `asset`의 JSON을 내보내고 `url`을 포함해야 한다. 원본의 투영은
`type`을 포함하고 MongoDB `_id`를 기본 보존한다. `_id`는 24자리 16진수 문자열이며
소문자로 정규화한다. API 목록의 `id`, MongoDB Extended JSON, 다른 컬렉션,
XLSX·CSV·최상위 배열은 이 계약에 포함하지 않는다. 실제 운영 서버의 버전·내보내기
설정이 다르면 이 계약과 맞는지 먼저 확인해야 한다.

## 화면과 API

자산 화면의 ‘ScopeSentry 가져오기’에서 다음 순서로 처리한다.

1. 같은 원본 인스턴스에 항상 같은 식별자를 입력한다. 영문·숫자·밑줄·점·하이픈,
   최대 64자이며 연결 주소나 인증 토큰을 넣지 않는다.
2. 파일 내용을 붙여 넣고 미리본다. UTF-8 1 MiB, 비어 있지 않은 줄 1–100개가 상한이다.
3. 새 자산·기존 자산 연결·기존 출처 확인·주소 변경과 가져올 수 없는 항목을 확인한다.
4. 반영할 항목을 선택하고 해당 주소의 검증 권한을 확인한 뒤 반영한다.
5. 결과와 자산 카드의 ‘출처’를 확인한다. 검증 작업 생성·실행 승인은 별도다.

관리자·운영자는 다음 API를 사용할 수 있다. 같은 워크스페이스의 조회자는
자산 출처를 읽을 수 있다.

- `POST /api/integrations/scopesentry/preview`: `{source_key, export}`.
- `POST /api/integrations/scopesentry/{preview_id}/apply`: `{selected, authorized}`.
  `selected`는 미리보기의 원본 ID 목록이고 `authorized=true`가 필요하다.
- `GET /api/assets/{asset_id}/sources`: 현재 연결의 SQL 검색·페이지.
  `history=true`는 해당 자산의 이전 연결을 조회한다. `search`, `limit`(기본 25, 최대 100),
  `offset`, `snapshot`을 지원한다. 삽입 watermark이며 과거 업데이트까지 고정하지 않는다.

미리보기는 만든 사용자에게 귀속되고 15분간 유효하다. 워크스페이스의 미만료
미리보기는 최대 50개다. 새 미리보기 생성 시 만료된 임시 기록을 정리한다.
본문·헤더·title·스크린샷·제품 정보·외부 접근 규칙 등은 저장하지 않는다.
반영되지 않은 후보에도 원본 ID와 유효한 URL 등 검토 필드만 임시 저장한다.
잘못된 URL·JSON 오류는 원문을 응답에 복사하지 않는다. URL 자체와 인스턴스
식별자는 의도적으로 저장되는 운영 정보다. 주소 경로의 비밀정보를 자동 판별하지 않는다.

미리보기에는 선택이 미리 체크되지 않는다. 반영 시작 후 선택과 입력을 잠그며
실패 시 같은 선택으로 확인할 수 있다. 미리보기와 반영 버튼은 중복 제출을 막는다.
미리보기를 닫으면 그 조회를 중단하지만 이미 보낸 반영 요청의 서버 커밋을 취소하지 않는다.

## 중복·변경·삭제와 무결성

출처 키는 `(source_key, external_id)`이며 현재 자산에 연결된다. 같은 주소는 기존
자산을 재사용하고 소유자·태그·API 규칙·revision을 덮어쓰지 않는다. 서로 다른 원본 ID나
인스턴스가 같은 자산을 가리킬 수 있다. 새 자산은 사용자가 권한을 확인한 URL로
기본 웹 자산을 만들며 규칙과 태그는 비어 있다. 이 과정은 실행 승인을 만들지 않는다.

같은 원본 ID의 URL이 변경되면 새 URL의 기존 자산 또는 새 자산에 연결한다. 이전
자산은 그대로 남기고 이전 출처 연결을 개별 이력으로 보존한다. 예전 작업의 범위·증거는
수정하지 않는다. 보관된 대상 자산은 자동 복원하지 않는다. 누락된 연결이나 중복된
기존 주소는 확인 후 다시 미리봐야 한다. 원본의 삭제나 파일에 없는 항목은 기존
자산·출처·증거의 삭제 근거가 아니다. 부분 파일로 전체 원본 상태를 추정하지 않는다.

출처에는 원본 ID·인스턴스·최초/최근 확인 시각·URL·미리보기 ID·파일 SHA-256이 남는다.
이 값은 운영자가 제공한 파일의 추적 정보이며 원본 서버의 인증·서명·진위 증명이 아니다.

선택 전체의 자산과 출처가 미리보기 이후 변경되면 409로 전부 거절한다. 반영은
SQLite `BEGIN IMMEDIATE`와 서비스 잠금 안에서 자산·출처·연결 이력·반영 결과·
해당 가져오기 감사 이벤트를 하나의 트랜잭션으로 저장한다. 어느 단계든 실패하면
모두 롤백된다. 공용 HTTP 요청 감사 이벤트는 이 트랜잭션과 별개다. 다른 서비스
작업의 비즈니스 데이터와 감사 이벤트까지 원자적이라고 주장하지 않는다.

같은 미리보기·같은 선택으로 동시 반영하거나 응답을 잃고 재시도하면 저장된 결과를
반환한다. 이미 반영한 선택을 바꾸면 409다. 재시도 보장은 해당 미리보기가 유효하고
보존되는 동안 적용된다. 만료 후에는 다시 미리보고 현재 상태와 대조한다.

## 남은 출시 검증

합성 내보내기·실제 콘솔의 오류 복구·SQLite 충돌/롤백·출처 이력 백업/복구 검증은 [검증 기록](VALIDATION.md)에
있다. 실제 ScopeSentry 운영 인스턴스, 원격 인증·페이지 중단/재개·원본 동시 변경,
대량 파일 분할 여정·이력 보존 정책·전체 모바일/보조 기술 검증은 남아 있다.
[출시 기준](V1-READINESS.md)의 ScopeSentry 전체 항목은 계속 미완료다.
