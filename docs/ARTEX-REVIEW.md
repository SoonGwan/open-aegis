# ARTEX 공개 기능 검토와 개발 기준

2026-10-04에 확인한 ARTEX `main`의 기준 커밋은
[`d0033724a63aefbbcc1ed022b0faf4dc4a1fce51`](https://github.com/Autumn-27/ARTEX/commit/d0033724a63aefbbcc1ed022b0faf4dc4a1fce51)이다.
[고정 README](https://github.com/Autumn-27/ARTEX/blob/d0033724a63aefbbcc1ed022b0faf4dc4a1fce51/README.md)의
설명과 현재 Open Aegis 구현을 대조했다. 아래 원본 설명은 문서상 기능이며,
ARTEX를 실행하거나 전체 코드를 감사한 결과가 아니다. 특정 국가·조직의 공격,
실제 침해나 정보 유출에 이 도구가 사용됐다는 주장도 확인하지 않았다.

## 원본의 기능 구조

| 분야 | ARTEX 공개 설명 |
|---|---|
| 콘솔 | 대시보드, 작업, 활동, 토큰 |
| 계획 | 목표 분해, Planner, 병렬 Worker |
| 진행 | 이벤트 기반 계획 재평가, 실행 큐 |
| 공유 | Worker 실행 과정 검색·조회 |
| 기억 | 여러 계획 회차의 공유 할 일 |
| 자산 | 도메인·IP·서비스·엔드포인트 그래프 |
| 탐색 | 목표·의도·사실·발견 그래프 |
| 연결 | 탐색 노드와 자산의 앵커 |
| 검증 범위 | 자산별 커버리지 시각화 |
| 통제 | 도구 실행 승인, 승인 상세 |
| 관찰 | MITM 프록시 트래픽 기록 |
| 보강 | DNS·HTTP 자산 보강 |
| 연동 | MCP, skills, ScopeSentry |
| 대화 | 사람의 실행 개입 |
| 재검증 | 독립 세션, 증거·결론 보존 |
| 운영 | PostgreSQL, SSE, LLM 설정 |
| 배포 | 컨테이너, 내장 UI 바이너리 |
| 갱신 | 체크섬 검사, 재시작, 이전 프로그램 복원 |

이 구성의 가치 있는 부분은 **자산 → 승인된 검증 → 근거 → 조치 → 재검증**을
추적할 수 있는 흐름이다. Open Aegis는 이 흐름을 독립적으로 구현한다.
아래 완료 조건은 이 프로젝트에서 정한 개발 기준이며 원본의 보장 사항이 아니다.

## 빠진 기능의 완료 조건

다음 조건을 충족한 구현과 실행 근거가 있어야 기능 비교표를 갱신한다.

1. **검토된 확장 도구 계약.** 고유 ID와 버전, 입력·출력 스키마, 필요한 권한,
   요청·시간·출력 예산을 선언한다. 등록 시 중복과 알 수 없는 필드를 거절한다.
   실행할 때 승인 스냅샷과 계약 버전을 다시 검사한다. 결과도 스키마 검사를
   통과해야 저장한다. 선언된 권한만으로 임의 Python·셸 실행을 허용하지 않는다.
2. **원격 MCP 클라이언트.** 서버 연결과 도구 실행 권한을 구분한다. 연결 주소,
   리다이렉트, 인증 전달, 도구 목록 변경, 출력 크기와 시간 제한을 검증한다.
   외부 도구는 기존 범위 검사를 우회할 수 있으므로 별도의 실행 격리와 계약
   검증 없이 기존 검증 도구처럼 취급하지 않는다. 중단·세션 만료·도구 변경을
   합성 서버로 재현한다.
3. **ScopeSentry 동기화.** 원본 식별자·출처·동기화 시각을 보존한다. 먼저
   가져올 항목과 충돌을 보여주고 명시적으로 반영한다. 반복 가져오기는 중복을
   만들지 않아야 한다. 원본 삭제가 기존 증거나 승인 범위를 삭제해서는 안 된다.
   가져온 항목만으로 실행 승인이 생기지 않는다. 실제 연동 계약을 확인한 후
   페이지 중단·재개·원본 변경·인증 실패를 검증한다.
4. **AI 대화·사용량.** 답변이 인용한 작업·증거 ID를 확인할 수 있어야 한다.
   질문, 답변, 실행 제안, 승인, 실행 결과를 구분한다. 대화에서 범위나 도구를
   바꾸면 새 승인을 받아야 한다. 제공자의 실제 usage와 누락·추정치를 구분하고,
   비용에는 모델·가격 출처·기준 시각을 남긴다. 오류 시 성공이나 사용량 0으로
   가장하지 않는다. 악성 응답의 실행 지시와 다른 작업 참조를 거절하는 검증도
   포함한다.
5. **PostgreSQL.** 저장소 계약을 먼저 고정하고 SQLite와 같은 동작을 검증한다.
   동시 승인·조치 버전·질문 중복 방지·감사 연결·보고서 스냅샷이 유지돼야 한다.
   이관은 건수와 참조를 검사하고, 실패 시 원본을 보존한다. 실제 DB의 백업·복구와
   세션 폐기를 실행한다. PostgreSQL 지원과 고객사 데이터 격리는 별도 완료 항목이다.
6. **갱신·롤백.** 검증 가능한 릴리스 출처와 아티팩트, 설치 전 백업,
   스키마 호환성 검사, 작업 중단 안내가 필요하다. 새 버전 시작 실패와 복구를
   실제로 재현한다. 프로그램만 되돌려도 데이터 스키마가 호환되는지 별도로
   판정한다. 체크섬 일치만으로 게시자의 신뢰를 보장한다고 표현하지 않는다.

UI 상태 복원, 접근성, 부하, 보존 정책과 배포 검증도 [출시 기준](V1-READINESS.md)의
별도 필수 항목이다. 위 여섯 분야를 구현하는 것만으로 v1이 완료되지 않는다.

## 독립 오픈소스 구현

ARTEX 저장소는 AGPL-3.0을 표시한다. Open Aegis는 원본 코드를 복사하지 않은
MIT 독립 구현이다. 이 검토는 기능 구조를 참고하기 위한 문서이며, 원본 코드의
라이선스를 변경하거나 재배포하는 작업이 아니다. 기능 참고와 코드 가져오기를
구분하고, 새 의존성을 추가할 때 해당 패키지의 라이선스와 출처를 기록한다.
