# Worker 관찰 링크의 출처와 작업 이력

엔드포인트 관찰은 승인된 기본 응답 HTML에서 발견한 범위 내 URL을 기록한다.
링크 자체를 방문하거나 링크의 접근 가능 여부·소유권·취약점을 검증하지 않는다.
기존 화면의 전체 관찰 목록과 검색은 유지하며 같은 URL도 서로 다른 작업에서
관찰하면 별도의 기록으로 남긴다. 화면의 작업 열은 해당 관찰의 출처 작업이다.

이전 ID는 자산 ID와 URL만으로 정해져 다음 작업이 같은 링크를 관찰하면 이전
작업 출처를 덮어썼다. 새 ID는 `[task_id,asset_id,check,url]`의 canonical JSON
SHA256이다. 같은 작업/자산/도구/URL의 중복은 같은 ID이고, 작업이나 Worker 자산이
다르면 별도 ID다. 이전에 이미 덮어쓴 출처는 이 변경으로 복원되지 않는다.
기존 기록을 새 출처로 꾸미거나 자동 재봉인하지 않는다. 데이터 스키마는2를 유지한다.

새 기록에는 `format:aegis-worker-observation-v1`, 작업·자산·Worker ID,
`check`, `tool_version`, 승인 당시 `scope_url/scope_revision`,
`package_sha256`, `created_at`과 `verified:false`를 저장한다. Worker ID는
작업과 자산의 조합이며 프로세스/사용자 신원이나 장치 인증 ID가 아니다.
다수 링크의 저장과 발견/커버리지 완료가 모두 하나의 원자적 트랜잭션인 것은 아니다.
중단·저장 실패 시 일부 관찰만 남을 수 있으며 조회 결과는 작업 완료 보증이 아니다.

## 작업별 HTTP·MCP 조회

`GET /api/tasks/{task_id}/observations`는 인증된 모든 역할에 해당 작업의 관찰
페이지를 제공한다. 기본25개/최대100개, `offset`, 삽입 상한 `snapshot`, 최대200자
`search`를 지원한다. 자산명·작업명·URL/출처 ID 검색은 기존 SQL 페이지와 같다.
존재하지 않는 작업은404, 범위를 벗어난 페이지 입력은422, 미인증은401이다.
작업과 관찰 페이지를 같은 읽기 DB 스냅샷에서 읽으며 PostgreSQL은 READ ONLY
REPEATABLE READ다. 페이지 snapshot은 삽입 상한이고 이후 수정의 고정 기록이 아니다.

읽기 전용 stdio MCP의 `list_task_observations`는 `id`와 같은 페이지 인수를 받는다.
기존 MCP 단일 읽기 트랜잭션·응답 크기 제한·SELECT 권한 계약을 유지한다. stdio는
HTTP 로그인/역할을 대신 검증하지 않는다. 조회는 대상을 요청하거나 새 작업을
계획/승인/실행하지 않으며 기존 작업 범위를 넓히지 않는다.

각 항목의 `provenance.status`는 다음 의미다.

- `matched`: 저장된 작업의 승인 시각과 범위, Worker/도구 ID·버전·observe-links
  선언, 승인 패키지 지문, 관찰 ID/URL·revision 메타데이터가 일치한다. 현재 자산이
  변경돼도 해당 작업의 승인 스냅샷을 비교하며 현재 코드 지문으로 과거를 무효화하지 않는다.
- `unconfirmed`: 출처 정보가 없거나 해당 메타데이터의 일치를 확인할 수 없다.
  레거시·손상/불일치 기록도 삭제하지 않고 이 상태로 보여준다. 다른 작업의 기록은
  해당 task_id 페이지에 포함하지 않는다.

이 상태는 저장된 메타데이터의 일관성이다. DB 수정 권한이 있는 공격자가 기록과
승인 정보를 함께 바꾸면 출처를 인증하지 못한다. 전자서명·Worker 신원 인증·HTML
내용의 진실성·링크 실행/취약점 판정·커버리지 완료를 보증하지 않는다. 링크와 이름은
외부 응답에서 온 신뢰할 수 없는 데이터이며 실행 지시로 해석하지 않는다.

## 확인한 동작과 남은 공유 기능

실제 소유한 loopback 서버에 두 작업을 순서대로 실행해 이전 관찰의 덮어쓰기를
수정 전 재현했고, SQLite와 PostgreSQL 모두 수정 후 두 출처를 보존했다. 조회는
추가 링크 방문을 하지 않는다. HTTP/MCP 검색·페이지·권한·역사적 범위·작업 변경 중
스냅샷과 메타데이터 불일치도 검증했다. 상세 결과는 [VALIDATION.md](VALIDATION.md)에 있다.

여기까지는 다른 클라이언트가 Worker 관찰을 출처와 함께 읽을 수 있는 경로다.
Worker 간 의존 단계·반복 Planner·관찰에 따른 다음 실행 제안/별도 승인·공유 할 일,
전체 모바일/보조 기술 검수는 아직 남아 있다.
전체 반복/Worker 공유 항목을 완료로 표시하지 않는다.

## 작업 상세 화면

전체 관찰 목록의 출처 작업 버튼은 원래 목록 검색·페이지를 유지한 채 작업 상세를
연다. 출처 작업 기록이 없으면 버튼을 비활성화한다. 상세의 **Worker 관찰 링크**는
작업별 25개 페이지·독립 검색·조회 오류/재시도를 제공하고 URL의
`task_observations_q`, `task_observations_offset`, `task_observations_snapshot`으로
위치를 복원한다. 출처 일치/미확인과 관찰 시각을 표시하며 키보드로 출처 메타데이터를
펼칠 수 있다. URL은 관찰 값으로 표시하며 링크 방문이나 실행 승인으로 연결하지 않는다.

`scripts/review_observation_ui.py`는 승인 실행 없이 합성 기록만 넣는 소유한 임시
검수 서버다. 320/390px 같은 출처 프레임과 선택적 503 플래그를 제공한다. 제품의
프레임 차단 정책은 변경하지 않는다. 종료 시 작업 상태·대상 요청 0개를 확인하고
임시 데이터를 제거한다. 이 검수는 실제 모바일 기기·터치·화면 읽기 도구 검수가 아니다.
