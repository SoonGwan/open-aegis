# 생성 시 작업 모델 선택

관리자는 `POST /api/tasks/with-models`에서 기존 작업 입력과 검토한 현재 프로필을 함께
저장할 수 있다. 최소 한 용도의 `planner`/`conversation` 프로필을 지정하며 생략한
용도는 워크스페이스 기본 선택을 따른다. 모델 선택은 대상 실행 승인과 별개이며
AI 대화 허용 설치 설정을 켜지 않는다. 일반 작업·템플릿·반복 예약·후속/재검증/재시도
생성은 기존 기본 선택 규칙을 유지한다.

```json
{
  "task": {"name":"배포 전 검증","asset_ids":["0123456789abcdef"],"checks":["security_headers"],"planner":"ai"},
  "models": {"planner":{"profile_id":"abcdef0123456789abcdef0123456789","expected_profile_revision":1}},
  "request_id":"reviewed-task-create-0001"
}
```

ID는 실제 등록한 ID로 바꾼다. 요청 ID는16–80자 ASCII 영숫자/밑줄/하이픈이다.
허용한 용도별 프로필 ID와 양의 안전 정수 현재 버전만 입력하며, 임의 제공자 주소·키·
명령·도구·시스템 지침을 받지 않는다. `task`에는 기존 자산/도구/Worker 의존 관계/
원격 실행 위치 검증을 적용한다. 현재 관리자 역할, 활성 프로필·검토 버전·인증 지문과
자산 스냅샷을 반영 트랜잭션에서 확인한다.

작업·커버리지·선택한 용도의 작업 모델 버전1/불변 이력·생성 영수증·감사는 함께
커밋하거나 함께 롤백한다. 생성 이벤트가 노출되기 전에 초기 선택이 존재한다.
선택 기록은 기존 작업별 모델 계약과 같은 형태이므로 첫 계획/기록 대화부터 포착한다.
이후 프로필 변경은 당시 생성 기록을 바꾸지 않으며 현재 모델 선택을 다시 검토해야 한다.

작업 ID는 계정/요청 ID에 묶인 결정적 ID다. 같은 현재 관리자·ID·정규화된 입력은
기존 생성 결과를 재확인한다. 결과는 불변 생성 메타데이터와 해당 원래 작업의 **현재**
상태를 반환한다. 재확인으로 과거 상태를 다시 저장하거나 다른 새 작업을 만들지 않는다.
변경한 입력의 같은 ID, 사라지거나 맞지 않는 원래 작업 참조는409다. 이미 저장한
결과를 다시 확인할 때도 현재 관리자 권한이 필요하다.

화면의 `모델을 선택해 작업 만들기`는 기존 자산/Worker 의존 관계/원격 위치 선택을
사용한다. 일반 생성과 별도 버튼으로 접근한다. 전송 전에 계정/요청 ID별 원래 중첩
작업/모델 입력을 해당 origin 브라우저 로컬 저장소에 보존한다. 작성 후24시간,
항목당 UTF-8 최대16KiB·계정당 이 기능 미확인20개다. 허용 필드/타입/의존 관계/
버전/시간/크기를 검증한다. 토큰·쿠키·인증 키·수신처 주소·응답 내용은 보존하지 않는다.
작업 이름/목표·자산 ID·도구·의존 관계·실행 연결 ID·검토 프로필 ID/버전은 브라우저에 남는다.

새 문서에서 원래 요청을 선택하고 **같은 요청으로 생성 결과 확인**을 눌러야 전송한다.
로드/선택만으로 생성하지 않는다.409는 원래 입력을 보존하며 현재 프로필을 명시적으로
조회/채택한 뒤 원래 작업 입력을 새 초안으로 복원하고 새 ID로 저장한다.
보존 실패는 전송 전에 중단한다. 명시적 정리/성공한 로그아웃은 브라우저 기록을 지우며
서버 작업을 삭제/취소하지 않는다. 서버 영수증이 남아 있을 때의 재확인 계약이며
삭제·복제·백업 롤백 뒤 외부 요청의 정확히 한 번을 보장하지 않는다.

## 현재 검수 범위

두 저장소의 생성/동일 요청 경합·최초 실제 계획/대화 제공자 호출·현재 작업과 원래
생성 기록의 분리·기본 선택 상속·일반 생성 유지·버전0/잘못된 타입/용도/추가 주소
거절·프로필/키/역할/자산 변경 거절과 감사 실패 롤백을 기존 모델 관련 검사와 함께
검수했다(128개 통과). 초기 버전0 제약이 기존 Annotated 타입의 하한에 덮인 문제는
재현하고 별도 양의 strict 정수 제약으로 수정했다. 자산 경합 테스트의 잘못된 저장소
fixture 호출도 실패로 보존한 뒤 실제 트랜잭션 API로 수정했다.

프런트엔드122개, TypeScript/production build와 디자인 검사를 통과했다. 실제 소유한
브라우저/서버에서는 생성503→새 문서→같은 ID/본문200으로 작업1개·초기 두 선택
버전만 유지했다. 프로필1→2의 실제409와 새 문서 복구/명시적 채택 후 원래 이름·목표·
자산·도구/계획 방식 유지·새 ID/버전2 저장도 확인했다. 결과는 원래 작업 상세의
현재 상태를 열었다. 생성 시 대상/모델 요청0건, 별도 승인은 수행하지 않았다.
소유한 저장 용량 오류 제어 화면에서는 추가 API/작업/영수증/선택 기록0건을 확인했다.
검수 탭/서버/임시 워크스페이스는 정리했다.

고정101 모듈 wheel의 두 저장소101→100→101 및 오프라인 백업/복원을 검수했다.
실제 생성 영수증·초기 두 선택/불변 이력·현재 작업 상태와 기존 연결/목록·모델/프롬프트·
알림·보관 기록, 명시적 합성 호출 스냅샷을 보존했다. 기존100은 작업 선택을 읽지만
새 생성 endpoint는405이며 유지보수 동안 AI 키/대화를 비활성화했다. 선택 기록의
보존 검수이며 이전 버전의 모든 실행/생성 API 호환성을 보장하지 않는다.
현재101 재확인·전환·복원은 제공자/대상 요청을 추가하지 않았고, 두 저장소에서 처음
의도한 추론 POST2개·목록 GET2개·알림 POST2개만 발생했다. 체크포인트/선택 행의
동일성·복원 세션0개·임시 자원 정리를 확인했다. 설치 wheel의 회귀·전체 native와
exact-source hosted 검증은 진행 중이다. 전체 모바일/보조 기술·장시간 운영·임의의 인증 교체 타이밍과 사용자
에이전트별 선택은 후속 범위다. v1/전체 ARTEX 기능/외부 운영 배포 완료를 뜻하지 않는다.
