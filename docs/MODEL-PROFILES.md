# 모델 프로필 계약

관리자는 고정 수신처의 모델 프로필을 최대25개 작성하고 계획·대화 용도별로 선택한다.
프로필은 기본 비활성이다. 활성화에는 현재 관리자 역할과 현재 수신처 인증 설정의
검토가 필요하다. 프로필 변경·키 교체·관리자 역할 철회가 일어나면 해당 용도 선택을
다시 검토해야 한다. 자동으로 다른 프로필을 호출하지 않는다.

프로필과 용도별 선택은 각각 최대200개 불변 버전을 보존한다. 현재 설정·버전·요청
영수증·감사는 같은 트랜잭션이다. 요청 ID는16–80자이며 같은 사용자·리소스·ID는
원래 결과를 재현한다. 이후 설정을 과거 버전으로 돌리지 않는다. 변경한 본문으로
같은 ID를 재사용하거나 검토 기준 버전이 달라지면409다. 이력과 목록은25개 SQL 페이지다.

설치자는 `AEGIS_MODEL_DESTINATIONS`에 최대10개 추가 고정 수신처를 지정한다.
각 항목은 `id`, `name`, `base_env`, `key_env`, 선택적 `lab_http`다. 예:

```json
[{"id":"company","name":"회사 제공자","base_env":"COMPANY_MODEL_BASE","key_env":"COMPANY_MODEL_KEY"}]
```

주소와 인증 키는 참조한 환경변수에서 읽는다. 화면은 고정 수신처 ID·이름·설정 여부만
표시하며 주소·키를 편집하거나 반환하지 않는다. 기존 `AEGIS_LLM_BASE_URL`,
`AEGIS_LLM_API_KEY`, `AEGIS_LLM_MODEL`은 기본 환경 설정으로 유지한다.
HTTPS가 기본이며 추가 수신처의 명시적 실험용 HTTP는 리터럴127.0.0.1/::1만 허용한다.
기존 네트워크 주소 검증·실행 소유권·응답 형식 검증이 호출에도 적용된다.
설정 확인은 실제 연결 성공이나 제공자 지원 모델 목록을 증명하지 않는다.
`AEGIS_LLM_CHAT_ENABLED=1`은 별도 설치 설정이며 모델 선택만으로 대화를 켜지 않는다.

호출 준비 시 모델·프로필 버전·용도 선택 버전·수신처 인증 지문을 고정하고 호출 직전
전체 설정이 일치하는지 다시 검사한다. 호출 중 설정 변경은 기존 호출 기록을 바꾸지
않는다. 키와 전체 수신처 주소는 호출의 일시적 메모리에서 사용하며 프로필 버전에는
저장하지 않는다. 호출 영수증은 기존 사용량·가격 계약에 따라 제공자의 origin
(프로토콜·호스트·포트)을 보존하고 경로·인증 키는 보존하지 않는다. 관찰과 최종 반영은 시작 스냅샷과 일치해야 한다. 같은 대화 요청
ID의 재확인은 제공자를 다시 호출하지 않는다. 사용할 설정이 없으면 계획은 기존
규칙 기반 검사를 사용하고 AI 대화는 이용할 수 없다. 모델 선택은 작업 실행 승인과 별개다. 시스템 설정의 호출 상세는 저장된 모델 선택·
프로필 버전과 프롬프트 추가 지침을 표시한다. 현재 설정으로 과거 기록을 대체하지 않는다.

화면은 응답 손실 뒤 원래 ID·본문·검토 버전을 유지한다. 충돌은 초안을 보존하고 최신
설정을 명시적으로 검토한 뒤 새 요청을 작성한다. 새 문서에서 미확인 저장을 복구하는
기능, 작업/에이전트별 모델 고정, 제공자 모델 목록·연결 시험, 장애 자동 전환, 모든
모바일/보조 기술 및 장시간 운영은 후속 범위다. 설치본 전환·전체 네이티브·브라우저
검수는 검증 기록이 추가되기 전까지 완료로 간주하지 않는다.

- `GET /api/models/configuration`: 인증된 수신처/용도 설정
- `GET|POST /api/model-profiles`: 인증된 목록/관리자 생성
- `GET|PUT /api/model-profiles/{id}`: 인증된 조회/관리자 버전 저장
- `GET /api/model-profiles/{id}/history`: 인증된 버전 목록
- `PUT /api/model-defaults/{planner|conversation}`: 관리자 용도별 선택
- `GET /api/model-defaults/{purpose}/history`: 인증된 선택 이력
