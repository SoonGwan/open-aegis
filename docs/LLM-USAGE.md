# AI 계획·대화 호출과 토큰 사용량

새 AI 계획 호출은 작업의 `llm_usage`와 같은 내용의 감사 이벤트로 보존된다.
두 기록은 하나의 SQLite 트랜잭션으로 저장한다. 감사 기록 실패 시 작업 메타데이터도
롤백한다. 현재 승인 작업마다 도구 순서를 정하는 호출 한 번이며, 재실행은 별도 작업이다.
기존 작업이나 이벤트를 수정해 과거 사용량을 만들어 넣지 않는다.

## 저장 계약

`model`은 서버에 설정한 모델, `observed_at`은 기록 시각이다. `outcome`은
`accepted`(승인된 도구 순서를 수용), `invalid_plan`(응답을 받았으나 계획 검증 실패),
`request_failed`(전송/응답 해석 실패) 중 하나다. 실패 시 규칙 계획을 사용하며,
확인 가능한 제공자 사용량은 계획을 거절해도 보존한다. 호출하지 않은 규칙 계획이나
LLM 설정 누락에는 호출 사용량을 생성하지 않는다.

현재 Chat Completions 호환 응답의 `prompt_tokens`, `completion_tokens`,
`total_tokens`만 처리한다. 필드의 의미는 [공식 토큰 설명](https://help.openai.com/en/articles/4936856-what-are-t)
및 [공식 SDK 사용량 계약](https://github.com/openai/openai-go/blob/main/completion.go)을
참고했다. 아래 상태·범위 검사는 Open Aegis에서 정한 호환 처리 정책이다.

| `tokens.status` | 의미 |
|---|---|
| `reported` | 세 필드가 모두 유효한 정수이며 합계가 입력+출력과 일치 |
| `partial` | 유효한 일부 필드만 있음; 없는 필드는 null |
| `missing` | 응답에 사용량 필드가 없거나 호출 응답을 확인하지 못함; 0으로 추정하지 않음 |
| `invalid` | 필드 형식/범위 오류 또는 합계 불일치; 비용·청구 근거로 사용하지 않음 |

정수 범위는 0–9,007,199,254,740,991이다. bool·문자열·실수·음수·범위 초과는
거절하며 해당 필드는 null이다. 잘못된 필드가 있어도 다른 유효한 필드는 남기되
상태는 invalid다. 제공자의 실제 0은 reported 0으로 보존한다. 불일치하는 합계도
원래 숫자를 남겨 불일치를 확인할 수 있게 한다. 누락된 합계는 계산해 채우지 않는다.
캐시/추론 세부 값·알 수 없는 필드·응답 본문·제공자 오류 문구를 사용량에 저장하지 않는다.

## 화면과 보고서

작업 상세의 ‘AI 계획 사용량’에 모델, 계획 결과, 사용량 상태, 입력/출력/합계를
표시한다. 미확인 값은 ‘미확인’으로 표시한다. 전체 또는 작업별 JSON 보고서의
작업 메타데이터와 Markdown 보고서에 호출 기록을 포함한다. CSV는 기존 발견 사항
보고서이며 사용량을 포함하지 않는다. 과거 사용량 이벤트는 실행 기록에서 그대로
조회할 수 있으나 새로운 작업 메타데이터로 소급 변환하지 않는다.

시스템 설정의 집계 카드는 계획·대화·전체 호출을 선택할 수 있다. 화면 기본값은
계획+대화다. `GET /api/llm/usage`의 기존 기본값은 계획 호출만 유지하며,
`?source=planner`, `?source=conversation`, `?source=all`로 범위를 선택한다.
`days=7` 또는 `days=30`을 함께 전달할 수 있으며 생략하면 전체 기간이다. 서버 시각 기준 조회 구간과 호출 수,
계획/대화별 호출 수, 네 가지 사용량 상태·수용/계획 거절/대화 거절/응답 실패/
알 수 없는 결과 건수, 형식 검증된 보고값 합계를 반환한다.
인증된 세 역할 모두 조회 가능하며 작업 원문·모델·자격증명은 반환하지 않는다.
화면은 응답의 호출 종류 메타데이터를 확인하여 이전 서버의 계획 전용 응답을
전체 집계로 표시하지 않는다. 서버/화면 형식 불일치는 오류와 재조회 안내로 표시한다.
조회는 감사 이벤트를 쓰지 않는다. 한 SQLite 읽기 스냅샷에서 작업별 마지막
`llm_usage`와 저장된 assistant 메시지의 `assistant_generation`을 집계한다.
질문·규칙 답변·메타데이터 없는 과거 기록·잘못된 시각·미래 기록은 제외한다.
전송 ID 재시도는 같은 답변을 반환하므로 추가 집계를 만들지 않는다.
감사 이벤트와 답변의 원자 저장이 실패하면 해당 사용량도 집계되지 않는다.
현재 실행 계약은 승인 작업당 계획 호출 한 번이다. 이 집계는 향후 여러 회차의
호출 이력이나 다른 서비스의 사용량을 포함하는 청구 원장이 아니다.

누락·일부·오류 상태는 합산하지 않는다. reported 기록도 정수 형식/범위와 합계를
다시 확인한다. 거절된 계획·대화의 유효한 보고값은 포함한다. 유효한 보고 기록이
없으면 합계는 null(미확인)이다. 실제 보고값 0이 있으면 문자열 "0"을 반환한다.
각 합계는 임의 정밀도 정수로 계산한 십진 문자열이다. SQLite sum 정수 상한이나
JavaScript 숫자 정밀도를 초과해도 반올림/오버플로하지 않는다. 전체 레코드를
Python 목록으로 읽지 않지만 SQLite가 대상 작업과 메시지를 순회하므로 대규모 조회 시간·
동시 부하·장시간 운영은 별도 검수 대상이다.

형식 검증은 제공자의 청구나 실제 모델 실행을 검증하지 않는다. 운영자 설정의
모델/제공자별 가격·통화·출처·기준일을 호출 전에 고정하고 단일 입력·출력 토큰
비용 추정과 통화별 부분 합계를 제공한다([비용 계약](LLM-COSTS.md)).
실제 청구 조회, 캐시/구간별 요금, 호출 시도별 사용량, 스트리밍 응답,
여러 계획 회차별 이력은 아직 구현하지 않았다.
TLS 합성 제공자와 저장/보고서 검증은 실제 상용 모델 호출과 구분한다.

작업 대화의 기본 답변은 제공자 호출이 없는 규칙 기반 요약이다. 선택적 AI 초안은
메시지의 `assistant_generation.tokens`와 같은 내용의 감사 이벤트에 보고 사용량을
원자적으로 저장한다. 거절된 답변도 제공자 사용량은 남기며 응답 실패는 미확인이다.
집계의 대화/전체 범위에 저장된 호출이 포함된다. 제공자가 호출됐지만 세션 폐기나
저장 실패로 답변을 남기지 못한 경우는 persisted 집계에 포함되지 않는다.
새 독립 시도 기록은 ledger=attempts로 관찰 사용량·비용과 결과 저장 상태를
집계한다([호출 시도 계약](LLM-CALLS.md)). 실제 제공자 청구 원장은 아니다.
인용·저장·현재 기록 링크와 남은 AI 대화 계약은 [CONVERSATION.md](CONVERSATION.md)를 따른다.


## 제공자 응답 크기

호환 제공자 응답은1 MiB 실제 바이트 한도를 유지한다. HTTP 파서가 확정한 본문
길이가 한도를 넘으면 본문을 기다리거나 버퍼링하기 전에 거절한다. 길이를 알 수
없거나 chunked이면 기존 한도+1바이트 읽기로 실제 크기를 검사한다. 정확히1 MiB의
유효한 JSON 응답은 수용한다. 기존8초 요청 제한·TLS/주소/리디렉션 검사도 유지한다.
한도 초과나 응답 실패의 원문은 사용량 기록에 저장하지 않고 미확인으로 처리한다.
