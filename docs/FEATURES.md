# ARTEX 기능 비교 및 구현 범위

ARTEX의 2026-10-04 공개 README 구성을 참고했습니다:
https://github.com/Autumn-27/ARTEX

Open Aegis는 독립 구현입니다. 아래의 ‘구현’은 해당 기능의 현재 범위를
뜻하며 ARTEX와 동등한 구현이나 검증 범위를 뜻하지 않습니다.

| 기능 | 현재 상태 | 구현 범위 |
|---|---|---|
| 대시보드·활동 기록 | 구현 | 실제 DB 기반 통계, SSE 및 재연결 |
| 목록 검색·페이지네이션 | 일부 구현 | 9개 주요 목록 SQL 검색·URL 복원, 발견별 증거·재검증 및 작업별 발견·이벤트 25개 페이지·독립 검색·출처 확인, 관찰 전체 건수·자산/작업 출처, 조회 오류 구분; 상세 URL·일부 내부 조회는 후속 작업 |
| 작업·계획 | 구현 | 규칙 계획, 선택적 LLM 도구 순서, 범위 스냅샷 |
| 병렬 Worker | 구현 | 작업별 최대 4개, 서버 동시 작업 1–4개(기본 2), origin 공유 속도·동시 제한 |
| 실행 제한·대기열 | 구현 | DNS·HTTP·작업·대기열 deadline, 진행 중 중지, 재시도 예산, SQL 상태 지표·정책 승인 |
| 실패 후 재실행 | 구현 | 현재 자산 revision·실행 정책의 새 승인 계획, 원본 연결·동시 생성 중복 방지 |
| 자산 관리 | 구현 | URL·담당자·태그·권한 규칙·JSON 가져오기·수정·보관·복원·범위 revision |
| 자산 보강·발견 | 일부 구현 | HTML에 노출된 범위 내 링크 관찰; DNS/포트 탐색 없음 |
| 자산·탐색 그래프 | 구현 | 자산·작업 선택, 실제 범위·검증·발견·증거·관찰 엣지, 필터·페이지·노드 이동·북마크·모바일 목록; 전체 워크스페이스 네트워크 지도는 제공하지 않음 |
| 발견 사항·증거 | 구현 | 안정적인 지문, 중복 통합, 원본 관찰, 담당자·조치 사유·변경 이력·동시 수정 충돌 방지 |
| 실행 승인 | 구현 | 작업 단위 범위·도구 승인; 도구별 사용자 규칙 없음 |
| HTTP 트래픽 기록 | 일부 구현 | 자체 검증 요청 메타데이터·해시; 범용 MITM/PCAP 없음 |
| 검증 커버리지 | 구현 | 활성 자산 × 6개 도구, 최신 승인·현재 revision, 실패·건너뜀·중지·재시작·이전 기록 누락 구분 |
| 수정 후 재검증 | 구현 | 재현·해결·판정 불가, 실패·판정 불가 시 상태 보존, 계획 이후 사람 결정 충돌 방지 |
| 보고서 | 구현 | 전체/작업별 Markdown, CSV, JSON 증거 묶음 |
| 사람과의 대화 | 일부 구현 | 저장된 작업 기록의 규칙 기반 요약; 실행 개입 대화 없음 |
| 워크스페이스·메모리 | 일부 구현 | 지속 노트·Worker 실행 기록; 자동 장기 기억 없음 |
| 에이전트 관리 | 일부 구현 | 역할·도구 조회, 작업별 Worker/Planner 설정 |
| LLM·토큰 | 일부 구현 | 서버 환경변수 설정, DNS·TLS·응답 시간 제한, 실제 HTTPS 호환 fixture, 호출 사용량 이벤트; 비용 대시보드 없음 |
| MCP | 일부 구현 | 읽기 전용 stdio 서버, 7개 조회 도구·SQL 페이지·출처 확인·관련 ID 요약·출력 제한; 원격 MCP 클라이언트 없음 |
| ScopeSentry | 미구현 | 현재 JSON 자산 가져오기 지원 |
| 예약 검증 | 구현 | 주기적으로 승인 대기 작업 생성, 오래 기다린 활성 예약부터 최대 100개 SQL 배치 처리 |
| 설정·인증 | 구현 | 관리자·운영자·조회자, 세션 폐기, 사용자·비밀번호 관리, 테스트 인증정보는 환경변수 |
| Docker·백업 | 구현·실행 일부 미검증 | Docker 파일 제공, SQLite 백업 검증·오프라인 복구·세션 폐기 |
| 원클릭 업데이트·롤백 | 미구현 | 소스 갱신·재빌드 및 이전 Git 버전 사용 |
| PostgreSQL·다중 테넌트 | 미구현 | SQLite·단일 공유 워크스페이스; RBAC는 구현 |
| 임의 Bash·자율 취약점 악용 체인 | 범위에서 제외 | 검토된 읽기 전용 검증 도구만 실행 |

## 다음 개발 우선순위

1. 상세 URL 상태, 보고서·대화 등의 조회 크기 제한 및 보존 주기. 주요 발견의 관련 ID 요약, 관찰을 포함한 목록과 MCP 페이지는 구현.
2. API 권한 정책 모델 개선: 기대 응답 스키마, 고객사 소유권, 재현 테스트 내보내기.
3. 실행 제한·큐 지표·조치 이력의 운영 부하·장시간 검증. 기능 동작, 실제 관계 그래프와 커버리지는 구현.
4. 팀·테넌트 분리, 감사 무결성, PostgreSQL 저장소. 역할별 권한은 구현.
5. 검토 가능한 확장 도구 인터페이스와 MCP 클라이언트 연동.
6. 서명된 릴리스, 데이터 마이그레이션, 백업 복구·업데이트 자동화.

새 기능은 동작 검증과 범위 통제를 갖춘 뒤 구현 상태를 갱신합니다.
