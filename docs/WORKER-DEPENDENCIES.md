# 승인된 Worker 의존 실행

작업 생성의 `worker_dependencies`는 후행 자산 ID를 선행 자산 ID 목록에 연결한다.
기본값은 빈 객체이며 모든 Worker가 독립적으로 실행된다. 선택한 자산 최대 20개,
연결 최대 40개다. 선택하지 않은 자산·자기 자신·중복 선행 자산·순환은 생성 시
422로 거절한다. 승인/실행에서도 저장된 관계를 다시 검사한다.

```json
{
  "name": "선행 관찰 후 후행 검증",
  "asset_ids": ["parent-id", "child-id"],
  "checks": ["endpoint_inventory", "security_headers"],
  "workers": 2,
  "worker_dependencies": {"child-id": ["parent-id"]}
}
```

`POST /api/tasks`는 운영자/관리자가 승인 대기 계획만 만든다. 관리자의 별도 승인이
필요하다. 승인 카드와 작업 상세에 선행·후행 자산의 이름/주소와 실패/건너뜀 시
차단 동작을 표시한다. 생성 폼의 의존 관계 편집 UI는 아직 없어 현재 API로 설정한다.
재실행/현재 범위 재계획은 관계를 보존한 새 승인 대기 작업이며 승인 없이 실행하지 않는다.

## 실행과 완료 근거

승인 시 `worker_dependency_contract`에 자산 목록·관계와 계약 형식을 저장한다.
실행 전 비교가 실패하면 `worker_dependency_changed`로 종료하며 대상 요청이나
AI 순서 계획을 시작하지 않는다. 이 저장 계약은 서명 또는 DB 관리자 변조 방지
보장이 아니라 승인/실행 간 변경 검사다.

준비된 Worker만 작업의 Worker 수(1–4) 안에서 실행한다. 합류는 모든 선행 Worker를
기다리고, 관계가 없는 Worker는 병렬 진행할 수 있다. 기다리는 후행 Worker가 실행
슬롯을 차지하지 않는다. 선행 Worker가 반환했다는 사실만으로 실행하지 않고 같은
작업의 승인 범위·도구/의존 계약·승인 시각과 저장된 도구별 완료 셀을 읽기 스냅샷으로
확인한다. 모든 선택한 검증 셀이 completed여야 한다. 누락·불일치·failed·skipped·
cancelled·interrupted는 완료 근거가 아니다.

후행 Worker는 `aegis-worker-handoff-v1` 입력을 받고 이벤트에 남긴다. 입력에는 선행
Worker ID·작업/자산·revision·도구 지문·완료 도구 목록, 출처가 일치하는 관찰 ID
최대 10개와 전체 건수/생략 여부가 있다. 최신 관찰 25개 중에서 선택하는 제한된
참조이며 전체 이력이나 완전한 관찰 모음이라고 주장하지 않는다. URL·응답 본문·
인증정보를 새 실행 입력으로 도입하지 않는다. 링크가 관찰되었다는 사실은 그 주소를
방문한 근거나 취약점 판정이 아니다.

선행 근거를 확인하지 못하면 후행 셀을 failed/WorkerDependencyBlocked로 기록하고
후행 자산에 요청하지 않는다. 그 후행에 의존하는 단계도 차단한다. 독립적인 완료
결과와 증거는 보존한다. 기존 작업 판정과 같이 일부 Worker가 검증을 완료하면 작업은
completed/오류 수로 남을 수 있으므로 전체 단계 성공 여부는 커버리지와 오류를 함께
읽어야 한다. 모든 Worker가 실행 실패/차단이면 작업 failed다.

중지·시간 초과 후 새 Worker를 시작하지 않는다. 실행 중인 Worker는 기존 소켓/
대기 중단 계약을 따르고 종료 결과를 회수해 처리 수를 기록한다. 시작하지 않은
후행의 미완료 셀은 취소/실패로 남긴다. 서버 재시작 시 미완료 작업을 interrupted로
처리하는 기존 복구를 유지하며 의존 단계를 자동 재실행하지 않는다. 과거의 완료
결과를 재사용해 새 승인 없이 실행하는 기능도 아니다.

## 범위와 남은 기능

모든 Worker는 작업에 이미 승인된 자산·도구만 실행하고 기존 자산별 요청 예산,
origin 공유 속도/동시성·작업 deadline을 사용한다. 관찰 주소를 새 대상 범위로
자동 확장하거나 외부 도구/명령을 실행하지 않는다. 선행 완료/관찰 참조의 전달은
구현했지만 현재 검증 도구가 다른 Worker의 URL을 실행 입력으로 사용하는 기능,
여러 회차 Planner의 적응형 제안·새 승인, 공유 할 일·대화 개입은 아직 남아 있다.
이 구현만으로 반복 Planner 또는 전체 v1을 완료로 표시하지 않는다.
