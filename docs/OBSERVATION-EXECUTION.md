# 선택한 Worker 관찰 응답 검사

종료된 승인 작업의 상세에서 **검사할 관찰 확인**을 누르고 최대10개 URL과
헤더·전송 보안·쿠키·CORS 검사를 선택한다. **승인 대기 계획 만들기**는 요청을
보내지 않는다. 새 작업의 선택 URL·자산 범위·도구·실행 제한을 검토하고 관리자가
승인하면 해당 URL의 GET 응답 설정을 검사한다.

## 계획 입력과 승인

`GET /api/tasks/{source_id}/observation-plan`은 읽기 권한 사용자에게 검증된
관찰 맥락, 사용 가능한4개 도구와 최대10개 선택 한도를 제공한다.
출처·완료 커버리지·현재 활성/권한 확인 자산의 URL/revision 검사는
[OBSERVATION-PLANNING.md](OBSERVATION-PLANNING.md)의100개/64KiB 계약을 따른다.
표본 밖 자료를 확인했다고 표시하지 않는다.

관리자·운영자의 POST 입력은 `fingerprint`, `observation_ids`, `checks`,
`request_id`다. request_id는32자리 소문자16진수이며 미확인 POST에는 같은 값과
동일한 입력을 사용한다. 출처+요청 ID의 결정적 작업 키와 저장된 입력으로
중복 생성 및 다른 선택의 재사용을 막는다. 이미 반영된 요청은 원본 관찰이
바뀌어도 같은 기존 작업을 돌려준다. 승인·실행을 재시도하는 동작은 아니다.

최종 쓰기 트랜잭션에서 맥락과 자산을 다시 확인하고 작업·커버리지·감사 이벤트를
함께 저장한다. 입력이 달라지면409이며 일부 계획을 남기지 않는다. 사용자가
직접 URL·범위·API 권한 규칙·도구 명령을 넣을 수 없다. 선택 URL은 서버가
확인한 관찰 항목에서 가져오며 자산 스냅샷은 등록된 원래 범위를 보존한다.

계획에는 Worker 관찰 맥락 및 선택 항목/출처/지문의 `observation_execution`을
저장한다. 승인 시 선택 입력·도구·범위 스냅샷의 계약 지문을 추가하고 실행 전에
검사한다. 내부 일관성/호환성 검사이며 DB 관리자에 대한 암호 서명은 아니다.
일반 Planner 맥락이 있다는 이유로 링크를 방문하지 않는다.

## 실행과 근거

선택한 자산의 Worker는 선택 URL만 요청하며 등록 자산의 기본 응답을 추가로
요청하지 않는다. URL당 응답을 같은 Worker의 선택 검사 사이에서 재사용한다.
공용 Transport의 범위/리다이렉트/DNS/주소 제한, 요청 수/속도 제한, 재시도,
중지·시간 제한을 사용한다. 리다이렉트·전송 재시도는 실제 요청 수에 포함되므로
선택 URL 수가 실제 HTTP 요청 횟수의 보장은 아니다. 인증 헤더를 자동 추가하지 않는다.

2xx 응답만 설정 검사 완료로 인정한다. 403/404/서버 오류/범위 밖 리다이렉트는
판정 실패다. 한 URL이 실패해도 나머지 URL의 증거를 기록하지만 해당 도구의
완료 상태는 실패다. 도구별 커버리지의 targets와 실행 이벤트에 URL별 완료/
실패/중지·오류 유형을 저장하며 화면에서 펼쳐 확인한다. 응답 원문·쿠키 값은
발견 증거에 저장하지 않는다.

발견 키에 URL 지문을 포함해 같은 자산의 서로 다른 응답과 기본 응답의 조치
상태를 합치지 않는다. 증거에는 요청 URL과 관찰 ID를 넣는다. 관찰 응답 검사는
등록 자산의 기본 응답 완료율을 대체하지 않으며 SQLite/PostgreSQL 최신 커버리지
집계에서 제외한다. 일반 next-plan의 기본 도구 분모에도 합치지 않는다.

재검증은 해당 발견의 같은 관찰 URL을 다시 선택한 새 승인 계획이다. 403 등으로
설정 검사를 완료하지 못하면 판정 불가이며 해결 처리하지 않는다. 재실행·대기
계획 교체도 같은 선택을 현재 출처 맥락으로 다시 확인한다. 현재 범위/출처에서
유효하지 않은 선택은409로 거절하며 임의로 기본 자산 URL로 돌아가지 않는다.

## 화면과 남은 범위

미확인 POST의 입력·요청 ID를 사용자/출처별 같은 탭 저장소에 POST 전 저장한다.
응답 유실/새로고침 후에는 선택을 잠그고 같은 요청으로 결과를 확인한다.
명확한409 거절 뒤 새 목록을 조회할 수 있다. 저장소를 사용할 수 없으면 요청을
보내지 않는다. URL 원문이 이 복구 저장소에 포함되지는 않는다. 새 탭·기기 간
복구, 전체 역할/탐색 경합·모바일/SR 여정은 별도 검수가 필요하다.

현재는 명시적 선택과4개 설정 검사다. 별도 [자연어 목표 계획](GOAL-PLANNING.md)의
분해 초안·승인 실행은 구현했지만 선택 URL 계획과의 통합, 관찰을 분석해 자동 실행
대상을 정하는 Planner, API 권한 규칙 자동 생성, 선택 검사의
자동 후속 회차/공유 할 일 연결, 원격 도구 등록과 외부 실행 격리는 남아 있다.
