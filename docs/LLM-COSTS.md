# 호출 당시 가격과 토큰 비용 추정

계획·대화 호출 전에 모델/제공자와 일치하는 운영자 설정 가격을 고정한다.
보고된 입력·출력 토큰이 모두 유효하고 합계도 일치할 때만 비용을 계산한다.
가격·통화·출처 URL·기준일과 계산값은 호출 기록 및 감사 이벤트에 함께 저장한다.
이후 설정을 바꿔도 기존 기록을 다시 계산하거나 과거 가격을 만들어 넣지 않는다.

이 기능은 **단일 입력·출력 단가의 추정**이다. 예를 들어
[공식 API 가격표](https://developers.openai.com/api/docs/pricing)는 100만 토큰 단위를
사용하지만 입력/캐시/출력·문맥 구간·처리 모드·추가 요금 등이 구분된다.
Open Aegis는 캐시·구간별 요율·서비스 모드·추가 요금·할인·세금·환율을 자동 계산하지
않는다. 실제 사용한 계약/요금에 맞는 가격을 운영자가 확인해야 한다.
출처 URL은 저장된 설정의 근거이며 서비스가 해당 페이지나 가격의 진위를 검증하지 않는다.
실제 제공자 청구 조회나 청구 원장이 아니다.

## 설정

`AEGIS_LLM_PRICES`는 최대 100개 가격의 JSON 배열이며 64 KiB까지 지원한다.
각 항목은 아래 필드만 허용한다. `.env`에는 한 줄로 입력하고 서버를 재시작한다.
JSON이나 URL에는 키·쿠키·계약 비밀을 넣지 않는다.

```json
[
  {
    "model": "owned-synthetic-model",
    "provider": "https://provider-fixture.invalid/v1",
    "currency": "USD",
    "input_per_million": "1.25",
    "output_per_million": "2.5",
    "source_url": "https://prices-fixture.invalid/synthetic-only",
    "as_of": "2026-01-01",
    "basis": "flat_text_tokens"
  }
]
```

위 주소·모델·가격은 **합성 예시**이며 특정 제공자의 실제 가격이 아니다.
`model`과 `provider`는 호출의 설정 모델과 BASE_URL(끝 `/` 제거)이 정확히 일치해야 한다.
같은 모델/제공자 항목이 둘이면 전체 설정을 거절한다. 모델은 1–200자이며 제어 문자를
금지한다. provider는 끝 `/` 없는 HTTPS 주소다. 합성 loopback 제공자만 HTTP를 허용한다.
source_url도 HTTPS이며 두 URL 모두 사용자 정보·query·fragment·공백/제어 문자를
거절한다. URL을 자동으로 요청하지 않는다.

통화는 USD/EUR/KRW/GBP/JPY/CAD/AUD/CHF/INR/BRL 중 하나다. 단가는 **문자열**이며
0–1,000,000·최대 소수 9자리, 지수 표기·음수·bool·숫자 JSON 값을 거절한다.
기준일은 유효한 YYYY-MM-DD이고 호출 시점 UTC 날짜보다 미래일 수 없다.
잘못된 필드·중복 키·초과 크기는 원문이나 오류 내용을 저장하지 않고 설정 오류로 기록한다.
가격 설정 오류는 LLM 호출이나 검증 작업을 중단시키지 않는다.

## 기록과 화면

새 계획의 `llm_usage.cost`, AI 답변의 `assistant_generation.cost`에 다음을 저장한다.
모델·결과·토큰·`started_at`·`observed_at`은 같은 호출 메타데이터에 있다.

| status | 의미 |
|---|---|
| estimated | 검증된 보고 사용량 × 호출 전에 고정한 단가; amount는 십진 문자열 |
| usage_unavailable | 유효한 가격은 있지만 보고 사용량이 일부/누락/오류; amount=null |
| unconfigured | 가격 배열이 비어 있음; quote=null, amount=null |
| model_unpriced | 가격 배열은 있지만 모델/제공자 일치 없음; quote=null, amount=null |
| invalid_configuration | 가격 설정이 계약에 맞지 않음; quote=null, amount=null |

금액은 `(입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가) / 1,000,000`이다.
단가의 소수 9자리를 정수로 변환하여 계산하며 float나 JavaScript Number를 쓰지 않는다.
표시도 금액 문자열을 그대로 사용한다. 0 사용량/0 단가의 실제 계산값은 문자열 "0"이다.
누락 금액은 null이며 0으로 추정하지 않는다. 거절된 계획/답변도 유효한 보고값이면 계산한다.

작업 상세와 AI 대화에 금액·미확인 사유 및 네이티브 ‘호출 당시 가격 근거’ 펼침을
표시한다. 단가·모델·통화·제공자·출처·기준일을 확인할 수 있다. 계획 메타데이터는 기존
JSON/Markdown 보고서에도 포함된다. 대화는 메시지 조회로 확인한다.

시스템 설정의 사용량 카드 및 `/api/llm/usage` 응답에 `costs`를 추가한다.
같은 읽기 스냅샷에서 선택한 계획/대화/전체와 기간을 적용하며 통화별 부분 합계와
계산 가능/미확인 건수를 표시한다. 서로 다른 통화를 합치거나 환산하지 않는다.
집계는 저장된 가격·모델·기준일·보고 토큰을 다시 검사해 금액이 정확히 일치하는 기록만
합산한다. 변경된 금액/모델·잘못된 가격은 invalid_record로 제외하고 오류 건수를 표시한다.
과거 비용 없는 기록은 unrecorded로 구분한다. 계산 가능한 기록이 없으면 totals=[]이며
미확인 안내를 표시한다. 계산 가능한 0원 기록은 통화별 "0"으로 표시한다.

## 보장 경계

저장에 성공한 전송 ID 재조회는 원래 답변/가격을 반환하며 추가 비용 기록을 만들지 않는다.
기록과 감사 저장 실패 시 해당 답변/계획의 가격·사용량과 연결 상태도 롤백된다.
새 호출의 독립 시도/관찰 기록은 먼저 보존하고 ledger=attempts 집계에 포함한다
([호출 시도 계약](LLM-CALLS.md)). 세션 폐기나 저장 실패로 답변이 없더라도 이미
관찰된 사용량·비용은 시도에 남는다. 관찰 저장 전 프로세스 종료 등으로 알 수 없는
사용량은 여전히 미확인이다. 실제 청구 대조나 모든 외부 청구의 원장은 아니다.
기존 감사 연결은 로컬 재작성의 진위를 보장하지 않으며 가격도 운영자가 설정한 값이다.
상용 제공자·실제 요금 계약 검증과 전체 모바일/스크린리더 검수는 별도 출시 조건이다.
