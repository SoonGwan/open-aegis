# 로컬 조회·보고서 부하 리허설

개발 환경의 Python 3.11+, httpx와 POSIX `ps`를 사용한다. Linux/macOS용이며
아래 명령은 실제 운영 서버가 아니라 별도의 임시 워크스페이스와 loopback 서버를 만든다.

```bash
.venv/bin/python scripts/review_resource_load.py \
  --duration 60 --assets 1000 --clients 4 \
  --output artifacts/resource-load-60s.json
```

`--duration`은 1–3,600초, `--assets`는 25–20,000개, `--clients`는 1–32개다.
자산 수와 같은 수의 합성 발견 사항을 생성한다. 실제 스캔 결과가 아니며
합성 URL은 `.invalid` 도메인이다. 승인·작업 실행·대상 네트워크 요청은 하지 않는다.
`AEGIS_*` 환경변수를 자식 서버에서 제외하므로 기존 데이터 경로·연동 설정을
사용하지 않는다. 부모가 확보한 socket을 자식에 전달해 포트 선택/시작 경합을 피한다.

각 클라이언트는 자산 25개 페이지, 최대 100개 목록을 포함하는 요약, 실행 지표,
전체 JSON 보고서를 순환 조회한다. 보고서의 정상 입장 제한 429와 양의 Retry-After는
정상 결과로 센다. 다른 HTTP 실패·JSON 오류·건수 불일치는 실패로 기록하고
최종 명령을 비정상 종료한다. 보고서는 자산 내보내기가 아니므로 합성 발견 사항
전체 건수를 확인한다. 실제 자격증명은 사용하지 않으며 합성 로그인 cookie도
출력에 포함하지 않는다.

서버 PID의 RSS(KiB)와 누적 CPU 시간을 약 2초 간격으로 측정한다. 시작·표본 최대·
끝 RSS, 부하 구간 CPU 시간, 마지막 최대 2,000개 정상/입장 거절 요청의 p50/p95,
끝의 운영 지표를 JSON에 기록한다. 표본은 마지막 1,000개까지 보관하되 관측한
전체 최대 RSS는 별도로 유지한다. Linux에서만 `/proc/<pid>/fd` 건수도 기록한다.
macOS에서는 해당 값이 null이며 FD 검증으로 해석하지 않는다.
Python/SQLite·주요 패키지 버전, CPU 아키텍처와 서비스 Python 코드 지문도 기록한다.

모든 클라이언트가 끝난 뒤 보고서 슬롯 0, 실행 작업 없음, 대상 요청 0을 확인한다.
서버를 종료하고 lifespan 완료 표시와 실제 워크스페이스 잠금 재획득을 확인한 뒤
합성 자산·발견 수와 작업/트래픽 0을 검사한다. Uvicorn이 정리 후 SIGTERM을 다시
발생시키는 환경에서는 exit code -15도 허용하지만 완료 표시와 잠금 검사는 생략하지 않는다.
임시 데이터는 제거하고 결과 JSON만 지정 위치에 남긴다.

이 검수는 메모리/지연 SLO를 설정하거나 강제하지 않는다. 2초 표본 사이의 순간 최대,
부모 테스트 클라이언트의 메모리, 실제 실행 도구·LLM·인증 실패 부하, 디스크 증가·보존,
느린 소비자·다수 SSE·네트워크 장애와 수 시간/수일 운영 안정성은 증명하지 않는다.
같은 코드 지문·시나리오에서도 기기와 동시 프로세스에 따라 결과가 달라진다.
제품의 장시간 부하·자원 한도 준비 항목은 별도로 계속 검수한다.
